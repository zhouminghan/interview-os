# 一句话

先明确三套 GMV 口径，再用「口径说明 + DWS 快照回冲 + 对账监控」三招解决不一致。

# 30 秒回答

对不上的根因通常是两边用了不同口径：商家后台看「支付后扣退款」，直播间实时报表常用「下单口径」。GMV 有三套：下单 GMV（付款前就计入，直播间常用）、支付 GMV（付款成功才计入）、有效 GMV（剔除退款和取消订单）。数仓侧按 ODS 原始订单 → DWD 订单明细 → DWS 直播间汇总分层，再用快照和 T+1 回冲处理滞后退款。

# 1 分钟回答

- GMV 口径：下单 GMV / 支付 GMV / 有效 GMV，三者的计入时点和剔除规则必须写进指标字典
- 数仓分层：ODS 原始订单、DWD 订单明细、DWS 直播间汇总层
- 解决一：明确两套口径，报表增加口径说明，让业务知道自己在看哪个
- 解决二：退款是滞后发生的，DWS 层做快照，T+1 更新退款回冲
- 解决三：增加对账链路——明细层和业务库对账，汇总层和商家后台指标对账
- 监控告警：识别大额延迟退款造成的指标偏差
