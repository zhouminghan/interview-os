# 一句话

ODS 先去重清洗，DWD 按事件发生时间归属自然日，再过滤机器流量，最后加抽样核对和波动监控。

# 30 秒回答

DAU 的核心是「当日去重活跃用户」，两个杀手分别是重复上报（虚高）和丢包（虚低），而且客户端本地缓存重试还会带来时间漂移。处理顺序是：先在 ODS 按设备 id + 事件时间做短窗口去重；再用事件发生时间而不是日志入库时间做自然日归属，避免重试导致的跨天错配；然后过滤爬虫和机器刷量；最后用抽样核对和波动告警兜底。

# 1 分钟回答

- ODS 接收原始埋点先清洗：按设备 id + 事件时间去重，短时间内的重复上报事件过滤
- 丢包问题：客户端本地缓存重试会产生时间漂移，DWD 层按事件发生时间归属自然日，而不是日志入库时间
- 区分真假用户：过滤爬虫、机器刷量
- 分层：DWD 用户行为明细 → DWS 日活汇总
- 校验：DAU 拆分渠道，和端侧 SDK 上报样本做抽样核对
- 监控：DAU 日波动超过阈值触发告警
