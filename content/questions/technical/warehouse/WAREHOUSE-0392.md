# 一句话

按「口径 → SQL → 数据 → 权限」四层定位：先看指标口径是否选错，再看生成的 SQL，再看底层数据，最后确认权限和过滤。

# 30 秒回答

这类问题的排查顺序很关键，直接从 SQL 入手容易走偏——Agent 取错数最常见的原因不是 SQL 写错，是指标选错（同名不同义）或者口径理解错（时间范围、过滤条件）。所以先看它选了哪个指标、用的哪套口径，再往下追。

# 1 分钟回答

- 第一层：确认 Agent 选的指标和口径是不是业务要的那个（同名不同义最常见）
- 第二层：看生成的 SQL——关联粒度对不对、有没有一对多导致金额算重、分区和时间范围对不对
- 第三层：校验底层数据——上游表是否延迟、是否有脏数据、快照是否回冲
- 第四层：确认权限和过滤——行级权限是否多过滤或少过滤了数据
- 兜底：让 Agent 输出口径说明和所用字段，业务能自己核对
- 长效：把这次的错误案例回流进评测集，避免重复发生
