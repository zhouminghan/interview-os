# 回答思路

1. 开口先说清操作对象：`ALTER TABLE ... PARTITION ... SET LOCATION` 改的是 metastore 里的分区路径元数据。
2. 接着回答数据去留：旧目录中的文件不会自动搬到新目录，也不会因为改路径而被删除。
3. 然后讲查询后果：改完之后查询按新路径读，新路径为空就会读到空分区，有文件则按新路径的文件格式和权限解析。
4. 最后给迁移顺序和验收：先复制文件并校验，再切换路径、检查分区信息和行数，确认无异常后才清理旧目录。

# 一句话

修改 Hive 分区的 `LOCATION` 只改元数据，旧文件仍留在原目录；查询会转向新目录，数据需要另行复制或迁移。

# 30 秒回答

我会先说这个操作不会搬家。Hive 把分区目录记在 metastore 中，`SET LOCATION` 只是把记录指向新路径，旧目录里的文件保持原样。切换以后查询会从新路径读；如果新目录还是空的，这个分区就会查不到数据。稳妥做法是先复制文件、核对数量和权限，再改路径并验证查询结果，最后单独安排旧数据清理。

# 1 分钟回答

第一，区分元数据和物理数据：分区的 location、文件格式、字段 schema 在 metastore，数据文件在 HDFS 或对象存储中，改 location 不触发文件移动。第二，讲落地步骤：先把文件复制到目标目录，确认目录权限、文件数、大小和格式与表定义兼容，再用 `ALTER TABLE ... PARTITION (...) SET LOCATION` 切换，并用 `DESCRIBE FORMATTED` 与 `SELECT COUNT(*)` 核对。第三，补边界：迁移过程中可能读到空分区或部分数据，最好安排停机窗口或双写/校验后再切；托管表和外部表都不应假设会自动搬文件，只读到新结果后才清理旧路径。

# 追问

- 旧目录的文件会被自动删除吗？回答要点：不会，`SET LOCATION` 只改元数据；旧数据是否保留或清理属于独立的存储管理动作。
- 新目录已有文件时会读哪一份？回答要点：查询按改后的分区路径读取新目录，旧目录不再对该分区生效，需确认新文件的格式、schema 与权限匹配。
- 怎样确认切换成功？回答要点：核对分区 `Location`、文件数量和抽样记录，再比较切换前后的分区行数或关键指标，避免路径改了但数据没到齐。
