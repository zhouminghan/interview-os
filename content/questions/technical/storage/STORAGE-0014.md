# 回答思路

1. 开口先按数据生命周期归属回答：两类表都由 metastore 管 schema 与 location，差别集中在 `DROP TABLE` 后的数据文件。
2. 接着讲默认行为：托管（内部）表删表时连表目录数据一起删，外部表默认只删元数据并保留文件。
3. 然后补一个常见误解：`EXTERNAL` 不等于只读，`INSERT` 仍会往该表 location 写文件。
4. 最后讲选型边界：共享或由上游管理的数据优先外部表，可重建的派生数据可用托管表，同时核对 purge 等版本相关配置。

# 一句话

Hive 内部表和外部表都维护元数据，区别在默认删除行为：前者由 Hive 管理数据生命周期，后者删表时保留底层文件。

# 30 秒回答

我会先说两种表不是「有没有元数据」的区别，它们都在 metastore 里记录 schema 和路径。真正的分界是 `DROP TABLE`：托管表默认把元数据和表目录数据一起删，外部表默认只删元数据，文件留给原系统或其他引擎继续使用。外部表也不是只读，写入时仍会操作它的 location；所以选型看的是谁负责数据生命周期，而不是看表面上的 ODS 层数。

# 1 分钟回答

第一，讲生命周期：托管表默认把数据放在 warehouse 目录，`DROP TABLE` 同时清理元数据和文件；外部表通常显式指定 `LOCATION`，删表后文件仍在。第二，讲读写和存储：外部表只是把删除责任交给外部系统，`INSERT`/`LOAD` 依然会往该路径写数据，分区元数据和物理文件仍可能不同步。第三，讲边界与选型：上游系统或其他引擎也要读同一份文件、删表不能丢原始数据时选外部表；可由作业完整重跑的派生结果适合托管表。但 `external.table.purge=true`、`DROP ... PURGE` 和版本差异会改变清理行为，落库前要检查建表语句和平台策略，不能只凭表名判断。

# 追问

- 什么时候优先用外部表？回答要点：当文件由上游或其他引擎共同拥有、需要保留原始数据或删表不应删除文件时用外部表；按数据归属决定，而非固定按数仓分层套用。
- 外部表的数据文件被外部系统删了会怎样？回答要点：metastore 中的表/分区元数据可能还在，查询会读到空结果或遇到路径错误，需恢复文件或同步/删除对应分区。
- 外部表能写入数据吗？回答要点：能，`EXTERNAL` 只改变默认删除生命周期，不表示只读；`INSERT` 会把文件写到该表的 location。
