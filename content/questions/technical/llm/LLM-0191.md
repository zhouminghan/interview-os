# 一句话

不是简单 NL2SQL，而是带数仓领域上下文的多轮对话 Agent：把自然语言需求转成可上线、可校验的数据开发产出，支持来回澄清口径。

# 30 秒回答

难点在于「可上线」三个字——生成一段能跑的 SQL 很容易，生成一个能进调度、有质检、有血缘、权限正确的开发产出很难。所以需要多个子 Agent 分工：解析意图、查元数据、规划方案、校验自检、执行反馈，外加记忆模块保存本轮确认过的口径。

# 1 分钟回答

- 意图与需求解析：理解用户是查指标、建表、改任务还是排查数据问题；绑定元数据词典，歧义点主动反问
- 元数据知识库：接入表、字段、指标、血缘、SLA、业务口径、数据字典、权限，Agent 不能凭空造表和字段
- 规划子 Agent：拆解需求，判断走离线 Spark、实时 Flink 还是简单查询，生成建模方案、建表语句、SQL、调度配置
- 校验自检 Agent：语法、字段合法性、数据类型、主键、分区规则、小文件、倾斜风险预判，并生成质检规则和对账 SQL
- 执行反馈 Agent：对接调度平台灰度运行，结果用自然语言回传，报错自动诊断给修复建议
- 记忆模块：保存本轮对话上下文，多轮追问时复用已确认的口径、时间范围、筛选条件
- 关键约束：权限隔离、幻觉防控、全链路可追溯
