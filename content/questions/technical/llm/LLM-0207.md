# 一句话

短期放会话上下文、长期落外部库按需检索；冲突时以当前会话的显式约束为准，历史记忆降为参考并标注来源与时间。

# 30 秒回答

记忆体系的难点不是存，是「什么时候该忘」和「听谁的」。过期口径、被纠正过的结论如果一直留在长期记忆里，会持续污染后续回答。所以每条记忆都要带时间戳、来源和置信度，写入前先做冲突检测。

# 1 分钟回答

- 短期记忆：当前会话上下文 + 结构化摘要（已确认口径、时间范围、筛选条件）
- 长期记忆：外部库按用户/项目分域存储，检索时按相关性和时效重排后注入
- 更新：新事实写入前检索相似记忆，做去重与冲突检测，冲突走版本化而非覆盖
- 遗忘：TTL + 访问频次衰减 + 被用户纠正即降权或归档，避免过期口径常驻
- 冲突处理：当前会话的显式指令优先；历史记忆标注时间与来源，只作参考
- 评测：构造「历史记忆与当前指令冲突」用例，检查是否按预期优先级
