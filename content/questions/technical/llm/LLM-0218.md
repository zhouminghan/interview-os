# 一句话

三层各补对方看不见的东西：规则扫描快且确定、污点分析追数据流找出隐蔽外泄、大模型审查判语义和意图，单一手段都会有盲区。

# 30 秒回答

美团 10-30 数据开发二面连问两题（第 7、8 题）。这是 Agent/Skill 平台岗的新八股，考的是能不能讲清「为什么不是只做一层」。

# 1 分钟回答

- 规则扫描：正则/AST 匹配硬编码密钥、危险 API（exec、文件读写、外发请求）、越权域名，毫秒级、零误报漏报争议，但只能认已知模式
- 污点分析：把用户输入、环境变量、内部数据标为 source，把网络外发、落盘、日志标为 sink，追踪数据流是否可达，能发现「读凭证 → 拼进 URL → 发出去」这类变形绕过
- 大模型审查：判断自然语言层面的意图和伪装，如 Prompt 注入、诱导越权、描述与代码不符、隐蔽后门，补前两层不懂语义的缺口
- 执行顺序：规则扫描先做低成本硬拦截 → 污点分析做数据流验证 → 大模型审查做语义复核，越贵越靠后，被前层拦截的不再进入
- 不可信层：LLM 审查本身会误判/被注入，只能给风险分和建议，不单独作为放行依据；高风险必须人工复核
- 误判处理：安全 Skill 被误判时走白名单 + 申诉复核 + 反馈样本回流，同时记录误判率指标，不能简单关掉规则
- 工程配套：审查拆独立服务是为了隔离不可信代码执行、独立扩缩容和超时控制；分层超时避免某个环节拖死整条发布链路
- 可观测：每层命中率、拦截原因、审查耗时、复审推翻率，用来持续调规则阈值
