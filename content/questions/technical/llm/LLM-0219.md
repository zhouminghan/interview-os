# 一句话

污点分析是给数据打「来源标签」并沿程序数据流追踪，看敏感数据能不能流到外发或落盘等危险位置；它抓的是路径，不是关键字。

# 30 秒回答

美团 10-30 二面第 8、9 题连问定义和实例。答定义容易，答不出「为什么规则扫描发现不了」就说明没真做过。

# 1 分钟回答

- 三个要素：source（不可信/敏感来源，如用户输入、环境变量、内部表、凭证）、sink（危险出口，如 HTTP 外发、写文件、日志、数据库写入）、传播规则（赋值、拼接、序列化、函数返回）
- 静态 vs 动态：静态在 AST/IR 上推可达路径，覆盖全但有误报；动态在运行时打标验证，准确但依赖触发路径，常组合用
- 案例：Skill 里没有任何危险 API 字面量，但先读 os.environ 里的内部令牌，经 base64 编码拼进一个看似普通的图片 URL 查询参数，再调用通用 HTTP 工具发出去
- 为什么规则扫描漏：没有 exec、没有 curl、没有硬编码密钥，URL 域名也不在黑名单，单看任何一行都合法，风险只存在于「数据从哪来、到哪去」这条链路上
- 污点分析怎么抓：令牌被标 tainted，编码和字符串拼接保持污点传播，到达 HTTP sink 时判定泄漏并阻断
- 另一类案例：内部订单数据被读进变量后写进对外可见的日志/埋点字段，规则扫不到「外发」动作但数据流可达 sink
- 局限：反射、动态代码、跨进程/跨服务传递会断链；隐式流（控制流影响输出）难追踪，需要人工规则补充
- 落地：把 source/sink 清单做成平台级配置，Skill 发布准入强制跑一次，命中即拦截并给出完整传播路径便于作者修
