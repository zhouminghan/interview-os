# 一句话

选型看规模、召回精度、写入吞吐和成本，更新一般做「增量 upsert + 定期重建索引」。

# 30 秒回答

小规模用 Faiss 这类库内存跑就行；亿级要上 Milvus/Vespa 这类分布式向量库，ANN 索引里 HNSW 召回高但吃内存，IVF+PQ 省内存但召回略低。更新上：新文档增量写，删除/修改用按 ID 删除再插入，索引膨胀了就定期重建，保证召回和查询性能不掉。

# 1 分钟回答

- 选型：规模、QPS、召回率、写入延迟、内存成本
- 索引：HNSW 快但内存大；IVF+PQ 内存友好但召回略低
- 更新：新增 upsert，删除先删后插，批量变更走离线重建
- 一致性：向量库侧重可用性和速度，强一致代价高，按业务接受延迟
- 降本：冷热分层，活跃向量放内存，冷数据落对象存储
