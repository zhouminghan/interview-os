RAG 方案设计：

**Chunk 策略**：不是按固定 Token 数切分，而是按 **语义单元** 切分。每张表的知识文件是一个 Chunk，每个指标口径是一个 Chunk，每个建模规范段落是一个 Chunk。这样保证检索到的每个片段都是完整的、自包含的信息单元，不会出现"一个表的元数据被切成两半"的情况。

**Embedding 模型**：使用腾讯内部的文本向量模型，对中文和 SQL 混合文本的理解效果比通用模型好。

**检索策略**：混合检索——向量相似度 + 关键词匹配（BM25）。纯向量检索容易被语义相似但业务无关的表干扰（比如"用户活跃表"可能匹配到多个域的活跃表），加上关键词匹配（表名前缀 `sgrp_` 限定频道域）可以大幅提升精准度。

**Top-K 策略**：检索 Top 5 → 重排序 → 取 Top 3 注入 Prompt。重排序用的是交叉编码器，综合考虑查询与文档的精确匹配度。

**Token 预算管理**：给 RAG 结果分配固定 Token 预算（约 3000-4000 tokens），超出就截断最不相关的 Chunk。核心表元数据优先级 > 口径定义 > 建模规范。
