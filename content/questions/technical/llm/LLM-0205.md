# 一句话

别把全部工具塞进上下文：先检索出候选工具，再按需加载描述，用结构化描述 + 负例把选择变成可评测的问题。

# 30 秒回答

工具从十几个涨到上百个，选错率会明显上升，原因是描述互相重叠、上下文被挤满。解法是「检索 + 分层加载」：先用轻量检索按意图召回 5~10 个候选，再只把这些的完整 Schema 注入上下文；同时把工具描述写成一个小而清晰的契约，并建评测集持续回归。

# 1 分钟回答

- 描述优化：一句话说清「什么时候用 / 什么时候别用」，补齐边界、前置条件、返回结构
- 负例与互斥说明：显式写出易混淆工具的区别，比堆正面示例有效
- 工具检索：工具名 + 描述 + 示例做向量索引，按用户意图召回候选集
- 动态加载：上下文只放候选工具完整 Schema，其余只留索引；Skill 按需渐进式加载
- 兜底：置信度低时反问用户或转人工，不允许模型猜一个工具硬调
- 评测：建「意图 → 正确工具」评测集，按工具数和相似度分层统计选对率
