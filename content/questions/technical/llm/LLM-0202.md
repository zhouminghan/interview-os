# 一句话

拆的是「想、做、验」三种职责，避免一个模型既当运动员又当裁判；汇总权必须落在确定性的编排层，不能让模型自己仲裁。

# 30 秒回答

单 Agent 把规划、执行、自检塞进同一个上下文，最容易出现「自己说自己做得对」。拆成三个角色后，Critic 拿到的是执行证据而不是自己的推理过程，判断才相对客观。但拆分不是越多越好——多了会带来上下文传递损耗和一致性问题，汇总与冲突仲裁一定要由代码层做。

# 1 分钟回答

- Planner：拆任务、定顺序、选工具、识别信息不足并发起澄清
- Executor：只执行被批准的计划，返回结构化结果与证据，不自行改计划
- Critic：对照计划和证据校验，判断是否需要重试、降级或转人工
- 为什么拆：职责隔离降低自检放水，便于分别评测和定位 Bad Case
- 汇总与冲突：编排层按预设优先级（硬规则 > 校验结果 > 模型判断）仲裁，冲突留痕
- 代价：多一轮模型调用、上下文传递可能丢信息，需要结构化消息契约
