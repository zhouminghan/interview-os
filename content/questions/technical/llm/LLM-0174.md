# 一句话

不按数仓的 ODS/DWD/DWS 主题分层，而是按「原始快照 → 清洗/去重 → 领域子集 → 训练数据集」的数据产品分层，存储走对象存储 + 列式文件，流转靠离线批处理 pipeline。

# 30 秒回答

Common Crawl 是网页级非结构化语料，和传统数仓的业务主题建模思路不同：核心不是「指标口径」，而是「数据质量与领域分布」。所以分层变成：原始 WARC/WET 快照落对象存储 → 解析成文本/JSON → 清洗去重（语言过滤、正文抽取、MinHash 去重）→ 按领域/任务切子集 → 打标后产出训练集，每层用 Parquet/ORC 列式 + 分区管理。

# 1 分钟回答

- 不分业务主题，分「数据产品」：raw → clean → dedup → domain subset → labeled dataset
- 存储：对象存储（S3/COS）为底座，列式 Parquet/ORC 承接结构化清洗结果
- 流转：离线批处理（Spark/Flink）为主，靠分区和 manifest 做增量
- 元数据：记录来源域名、语言、质量分、去重指纹，支撑筛选
- 与传统数仓最大的差异：主题域服务于指标分析，训练数据服务于模型效果
