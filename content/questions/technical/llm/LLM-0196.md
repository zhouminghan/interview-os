# 一句话

五类：截断、历史摘要压缩、外部持久化检索、分块并行处理、长上下文模型；按「是否需要保留全部细节」选型。

# 30 秒回答

这不是背方案清单的题，面试官想听你怎么选。判断依据是：后续还要不要用到早期细节。对话类场景用截断或摘要压缩就够；需要长期引用历史的分析类场景，要持久化到外部库再按需检索；超长单文档（如整本制度文件）走分块并行再合并。

# 1 分钟回答

- 直接截断：最简单，适合只关心近期对话的场景，风险是丢失早期约束
- 历史摘要压缩：把早期对话压缩成结构化摘要（已确认口径、时间范围、筛选条件），性价比最高
- 持久化 + 检索：对话历史存外部库，按需检索回填，适合长周期、多轮的项目型对话
- 分块并行：超长文档切块分别处理再合并，注意块间重叠避免切断语义
- 成本视角：摘要压缩能同时降低 Token 消耗和延迟
