遇到过。最典型的场景是 Agent 从知识库里检索到了一张表的元数据，但误解了某个字段的含义，然后基于错误理解生成了 JOIN 条件。

防止措施三层：

1. **上下文收敛**：不给 Agent 太多无关信息。每次 RAG 检索只返回最相关的 2-3 张表的元数据，不是全量灌。信息越少，幻觉空间越小。
2. **强制引用来源**：Prompt 里要求 Agent 在 Thought 阶段必须标注"我依据的是哪张表的哪个字段"，如果标注不出来说明信息不足，必须请求补充而不是瞎猜。
3. **阶段性校验**：每个 Thought-Action-Observation 循环结束后，如果涉及 JOIN 或字段引用，质检引擎会校验引用的字段是否确实存在于该表、数据类型是否匹配。不匹配就打回重新推理。

最核心的原则：**宁可让 Agent 说"我不确定，请 DE 确认"，也不让它编造一个看起来合理的答案。** Prompt 里明确写了"当信息不足以做出判断时，输出 UNCERTAIN 并暂停"。
