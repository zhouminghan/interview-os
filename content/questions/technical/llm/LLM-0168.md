以前 DE 做一个建模需求的信息收集流程：
1. 登录 **WeData** 查表结构和分区状态
2. 打开 **数据地图** 查血缘关系
3. 翻 **飞书文档/Wiki** 找口径定义
4. 上 **TDW** 跑验证 SQL 看数据分布
5. 打开 **US 调度系统** 查任务依赖关系

5 个平台，来回切换，光找信息就 1-2 小时。

现在通过 MCP 统一后，DE 在一个对话窗口里说"帮我查一下 dws_xxx 表的结构、上下游血缘、和相关口径"，Agent 在后台：
- 调 WeData MCP Server → 拿到表结构
- 调血缘 MCP Server → 拿到上下游依赖图
- 调知识库 RAG → 匹配口径文档

5 分钟内在一个界面里返回结构化结果。DE 不需要登录任何平台，不需要记各个平台的入口和操作方式。

关键改进：**从"人去找信息"变成"信息来找人"**。MCP 的价值不仅是技术层面的统一接口，更是 UX 层面的认知负担降低。
