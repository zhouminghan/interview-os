参数提取流程是 **LLM 结构化抽取 + 规则校验** 两步走：

**第一步：LLM 结构化抽取**。用户说"帮我建一张频道用户活跃的 bitmap 表，粒度是 channel_id + uin，需要记录发言、点赞、浏览三个行为"。LLM 按 Schema 抽取：
```json
{
  "table_type": "bitmap",
  "granularity": ["channel_id", "uin"],
  "behaviors": ["msg", "like", "view"],
  "partition": "di+df",
  "source_table": null  // 未明确指定
}
```

**第二步：规则校验 + 补全**。
- `source_table` 为空 → 去知识库匹配：粒度是 channel_id+uin 且包含行为数据的表 → 命中 `dwd_sgrp_user_action_detail_di`，回填
- `behaviors` 里的自然语言映射到标准 action_type → "发言"→"msg"、"点赞"→"like"、"浏览"→"view_post"

**提取不准的情况**：
- 用户说"活跃"但没说具体是哪些行为算活跃 → Agent 追问
- 用户给了表名但拼写错误 → 模糊匹配知识库里的表名 + 确认
- 用户说"跟那张大宽表一样的粒度" → 需要上下文记忆，从会话历史里查"大宽表"是哪张

兜底：如果 LLM 抽取的参数有任何一个必填字段为空或标记为 uncertain，不执行模板渲染，而是生成追问消息。
