type: technical
question: 你的 Skill 是怎么被路由（Routing）的？当用户输入一个模糊需求时，Agent 怎么判断该调哪个 Skill？有没有遇到过路由冲突或误触发的问题？
difficulty: 0
topic: []
source_type: knowledge
---

路由机制是 **意图分类 + 关键词匹配 + 上下文条件** 三层叠加：

1. **意图分类（主路由）**：用 LLM 做意图识别，把用户输入映射到预定义的意图标签（如 `create_table`、`data_backfill`、`export_to_kafka`、`generate_doc`）。每个 Skill 绑定一组意图标签。
2. **关键词匹配（加速器）**：对于高确定性的触发词直接短路到 Skill，不走 LLM 推理。比如用户说"帮我建一张 bitmap 表"，"bitmap"+"建表"直接路由到建模 Skill。
3. **上下文条件（守卫）**：即使意图匹配了，还要看用户当前上下文。比如用户在回溯流程的第三步说"生成 SQL"，这时候该路由到回溯 Skill 而不是建模 Skill——通过检查当前会话状态来消歧。

**路由冲突的例子**："帮我看看这张表的情况"——是要查元数据（表知识 Skill），还是要查数据质量（质检 Skill），还是要查血缘（血缘查询 MCP）？

解决方式：
- 优先级排序：给 Skill 设置 priority，模糊情况下走优先级高的
- 追问兜底：如果 LLM 意图分类的置信度 < 0.7，不默认执行，而是反问用户"你是想查表结构还是数据质量？"
- 实测误触发率约 5%，大部分被追问机制拦住了
