> **来源面经**：小红书-AI数据工程师5轮-20260530 Q10

向量是把内容/用户/图片通过模型压缩成的固定维度浮点数组（如 768 维），核心用途是**相似度检索**——召回阶段找最像的 Top K，比传统倒排索引能捕捉语义。

**存储分层选型**：
- **专业向量库**（Milvus / Faiss / Vespa / Pinecone）：主存，亿级 + ANN 索引（HNSW / IVF / PQ）
- **Redis**：缓存活跃 Top 1% 用户向量，毫秒级返回
- **HDFS / 对象存储**：原始向量冷备 + 离线训练
- **关系型库 / Hive**：存元信息（向量 ID → 业务 ID 映射、版本、时间），不存向量本身

**性能优化方向**：
- **索引选型**：HNSW 召回率高、查询快、内存占用大；IVF + PQ 内存友好但召回率略低，适合超大规模
- **分片**：按品类或哈希分片，每片单独建索引并行查询
- **批量写入**：避免单条写入，攒批 flush 提升吞吐
- **冷热分离**：热数据（近 30 天）放内存索引，冷数据放磁盘 SSD
- **索引重建策略**：增量插入会让 ANN 索引退化，定期全量重建保持召回率
- **维度压缩**：PCA 降维或量化（PQ/SQ）大幅省内存

> 💡 **专家补充**
>
> - **向量库 = "AI 时代的搜索引擎"**——传统倒排索引解决"关键词匹配"，向量索引解决"语义相似"，两者并存而非替代
> - **HNSW vs IVF 的选型本质是"内存换召回率"**——业务允许内存预算大用 HNSW，超大规模成本敏感用 IVF+PQ
> - **向量库还在快速演进**——2024-2026 年是大爆发期，Milvus / Vespa / Qdrant 都在迭代，选型时要看 1 年内是否有大版本变更
