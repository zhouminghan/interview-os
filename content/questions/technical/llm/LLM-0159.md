Skill 从需求到上线的流程：

1. **场景识别**：统计过去 2-3 个月的高频开发动作，找到重复率 ≥ 3 次/周的模式化操作。比如"建 bitmap 表""数据回溯""出库到 Kafka"。
2. **模板抽取**：把这些操作的 SQL 模式、配置模板、操作步骤抽象出来，写成 Skill 的骨架文档（SKILL.md）。
3. **Prompt 工程**：定义 Skill 的输入 Schema（用户需要提供什么参数）、执行逻辑（分几步、每步干什么）、输出 Schema（最终产物的格式）。
4. **测试验证**：用历史真实需求做测试集，跑 10-20 个 case 看产出质量。不合格的迭代 Prompt 或补充约束规则。
5. **质检规则配套**：每个 Skill 配套对应的质检规则，上线后自动校验。
6. **上线 + 监控**：上线后跟踪调用成功率和人工修正率，如果修正率 > 20% 就迭代优化。

**粒度原则**：一个 Skill 对应一个「完整的业务动作」，不对应一个 SQL 语句。比如：
- ✅ 建模 SQL 生成（包含建表 DDL + ETL 逻辑 + 质量规则）= 一个完整动作
- ❌ 只生成 SELECT 语句 = 太细，不够独立
- ❌ "数仓开发全流程" = 太粗，应该拆成需求澄清 Skill + 建模 Skill + 回溯 Skill

判断标准：**用户能用一句话描述触发意图，Agent 能用一次 Skill 调用完成交付物。**
