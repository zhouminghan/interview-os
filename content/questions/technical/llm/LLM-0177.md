# 一句话

先澄清规模、时效、成本，再按「清洗去重 → 分块 → embedding → 向量库 + 评估集」串起来，每步都想清楚失败怎么兜底。

# 30 秒回答

拿到题目别急着堆组件，先问清楚：数据量多大、SLA 要多久刷新、吞吐多少、要不要容错、下游谁消费、成本上限多少。然后管线分四段：网页清洗去重（垃圾页、低质、重复）、分块、embedding 生成（离线批量为主，实时增量走流式）、写入向量库，同时留一份带标注的评估集做质量把关。降本主要砍 embedding 和向量库这两块的开销。

# 1 分钟回答

- 澄清问题：数据规模、新鲜度 SLA、吞吐、容错、消费方、成本约束
- 清洗去重：HTML 解析抽正文、低质页过滤、MinHash/SimHash 近重复去重
- 分块：按语义单元切，别硬按固定 token 切
- embedding：离线批量是主链路，实时增量走流式，扩容按吞吐加 worker
- 向量库：选型看规模/召回/成本，单独维护评估集验证检索效果
- 降本：批处理合并 embedding 调用、缓存热门文档、向量库冷热分层

- 文档更新了向量库怎么增量同步？
