# 一句话

把「能不能做」从模型判断里拿走：动作分级 + 硬规则拦截 + 金额阈值 + 人工确认 + 全链路审计，模型只负责理解和提议，不负责放行。

# 30 秒回答

平安科技 09-08 一面拿退款当例子问这题，考的是有没有意识到 Agent 出错的代价不是「答错」而是「资损」。只答「加个 Prompt 约束」基本会被追问到穿。

# 1 分钟回答

- 动作分级：只读查询可自动执行；写操作按资损/不可逆程度分 L0-L3，退款、改价、发券、删数据一律进高等级
- 硬规则前置：金额上限、单用户频次、白名单商户、时间窗等用代码校验，不进 Prompt，模型无权绕过
- 权限隔离：Agent 用独立服务账号，最小权限 + 按业务域授权，高风险接口需二次鉴权或双人复核
- 人机确认：超过阈值生成待办单据由人工点确认，Agent 只做信息收集与方案草拟，确认前不落库
- 幂等与回滚：每次动作带 business_id 做幂等键，写前留快照，配套反向补偿流程，杜绝重试造成重复退款
- 审计可追：记录输入、检索依据、模型版本、工具参数、规则命中、审批人，支持事后逐笔复盘
- 兜底：检测不到规则或置信度低时默认拒答/转人工，异常路径必须 fail-closed 而不是 fail-open
- 评测：用越权、诱导注入、参数篡改的 Bad Case 集做回归，指标看误放行率而非只看成功率
