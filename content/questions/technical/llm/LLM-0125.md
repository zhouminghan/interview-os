> **来源面经**：阿里系-AI数据工程师两面-20260521 集团2-Q7.2

通用 AI Agent 的核心能力可以拆成 **5 个组件**，缺一不可：

**1. LLM（大语言模型）—— 大脑**
- Agent 的推理引擎，负责理解意图、规划步骤、生成结果
- 选型考虑：能力（GPT-4 / Claude / 国产大模型）、上下文长度、成本、推理速度

**2. Memory（记忆）—— 上下文管理**
- **短期记忆**：当前对话的上下文（聊天历史 + 中间结果）
- **长期记忆**：跨会话的用户偏好、历史交互（向量数据库存储）
- **工作记忆**：当前任务的中间状态（如 Agent 多步执行的中间产物）

**3. Tool Use（工具调用）—— 手脚**
- Agent 不只是聊天，能**真正操作外部系统**——查数据库、调 API、写文件
- 通过 **MCP 协议** 或 **Function Calling** 标准化工具接口
- 数据工程场景的工具：查表元数据、跑 SQL、查分区、建任务

**4. Planning（规划）—— 思维链**
- 复杂任务拆解：把"帮我建一张 DWS 用户互动宽表"拆成「查上游表 → 设计字段 → 生成 DDL → 注册任务 → 配置调度」
- 主流方法：**ReAct**（Reason + Act 交替）、**Plan-and-Execute**（先规划后执行）、**Reflexion**（自我反思）

**5. Knowledge Base / RAG（知识库 / 检索增强）—— 业务上下文**
- 业务知识、表结构、指标口径作为 Agent 的"教科书"
- **RAG**（Retrieval-Augmented Generation）：用户提问 → 向量召回相关知识 → 拼到 Prompt 里 → LLM 基于知识回答
- 解决"幻觉"和"业务无关"两大顽疾

**回答口诀**：「Agent = **LLM 大脑 + Memory 上下文 + Tool Use 手脚 + Planning 规划 + Knowledge Base 知识**——大脑想清楚（Planning），从知识库取上下文（KB+Memory），再用工具去执行（Tool Use），整个过程通过 LLM 串起来。」

**项目落地举例**：我们的数据回溯 Skill 就是一个完整 Agent 应用——LLM 做规划、Memory 记住会话上下文、Tool Use 通过 MCP 调天穹/WeData/THive 元数据接口、Planning 用 ReAct 交替"查上游表 / 判断是否就绪 / 输出回溯计划"、Knowledge Base 提供频道业务域和表知识。

> 💡 **专家补充**（大数据架构师视角，面试中视情况展开）
>
> - **5 个组件的成熟度差异巨大**——LLM 和 Tool Use 已经工业级成熟，Memory 还在快速演进（Mem0 / LangMem 等开源项目），Planning 还远未成熟（多步任务失败率仍高）
> - **「Agent = LLM + 工具 + 记忆 + 规划」是 2024 年开始的业界共识**——LangChain、AutoGPT、Claude Code、Cursor 等产品都遵循这个 5 组件模型，只是重心不同（如 Claude Code 重 Tool Use，AutoGPT 重 Planning）
> - **数据工程场景的特殊性在于「Tool Use 必须有强幂等和审核」**——Agent 不能直接 DROP TABLE，所有破坏性操作必须走「生成方案 → DE 审核 → 执行」三段式
> - **回答这题最容易踩的坑是只讲 LLM**——很多候选人把 Agent 等同于"会调 ChatGPT"，少了 Tool Use / Planning / KB，体现不出 Agent 工程的实战经验
