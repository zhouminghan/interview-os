# 一句话

四条路线：直接 Text-to-SQL、Schema Linking 增强、RAG 辅助生成、语义层编译；企业里推荐两段式，因为口径要可控、可审计。

# 30 秒回答

直接让模型写 SQL 看起来最灵活，但企业环境有三个硬伤：表太多选不准、口径藏在 SQL 里没人能审、同一个问题每次生成的 SQL 可能不一样。更稳妥的是两段式：模型只负责把自然语言翻译成结构化查询意图（指标 + 维度 + 过滤条件），SQL 由语义层确定性地编译出来，口径完全由语义层控制，模型只是一个翻译。

# 1 分钟回答

- 对比维度：灵活性（Text-to-SQL 高 / 两段式受限于已定义指标维度）
- 口径一致性：两段式强，口径由语义层唯一定义；Text-to-SQL 每次可能不同
- 可审计性：意图结构清晰业务也看得懂；Text-to-SQL 需要人读懂 SQL
- 准确率：常见指标问题两段式高且稳定；表多逻辑复杂时 Text-to-SQL 明显下降
- 适用：两段式覆盖高频标准指标问题（占大多数），Text-to-SQL 兜底长尾灵活查询
