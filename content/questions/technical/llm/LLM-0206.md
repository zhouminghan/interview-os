# 一句话

资源设单一 Owner，Agent 之间靠消息申请变更；进度和失败统一由编排层的状态机广播，不让各 Agent 自己协商。

# 30 秒回答

这题本质是并发控制，别往「让模型互相沟通」上答。模型之间的自然语言协商不可靠也不可审计，正确做法是把冲突处理下沉到代码层：谁有写权限、按什么顺序、失败怎么回滚，都是确定性规则。

# 1 分钟回答

- 资源归属：同一资源指定单一 Owner Agent，其他角色通过申请消息提交变更意图
- 并发控制：字段级乐观锁 / 版本号，提交时校验版本，冲突则拒绝并回传差异
- 进度同步：编排层维护状态机，事件广播给相关 Agent，各 Agent 不自行推断全局进度
- 失败同步：失败事件带错误分类与幂等键，编排层决定重试、降级或整体回滚
- 可审计：每次变更留下谁发起、谁批准、改了什么、结果如何
- 避免：让多个模型用自然语言「讨论」后各自写入

# 追问

- 状态机放哪里？重启后怎么恢复？
- 怎么验证没有重复写入？
