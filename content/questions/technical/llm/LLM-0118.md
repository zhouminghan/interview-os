> **要点提纲**：业务知识库覆盖度 | Skill 颗粒度 | MCP 工具链完整度 | 评测体系 | 上下文窗口
> **来源面经**：字节-AI Agent数据开发一面-20260412 Q1
> **来源面经**：腾讯 CDG-数据工程秋招一面-20261005 Agent Q3

AI + 数据工程体系目前还在半自动化阶段，效果差有几个原因。

**第一是业务知识库覆盖度不够**。频道有几百张表、几十个业务域，目前只沉淀了核心域的表知识文件，AI 在涉及非核心域时容易"幻觉"——字段命名不规范、分区字段写错。

**第二是 Skill 颗粒度太粗**。比如建模 Skill 一上来就让 AI 生成完整 SQL，但实际业务规则太复杂，应该拆成"识别建模模式 → 选择模板 → 填充参数"几步，让人在中间能干预。

**第三是 MCP 工具链不完整**。平台侧目前提供的 MCP 工具集中在元数据查询和任务创建，像血缘解析、分区状态批量查这些核心能力还在补齐，导致回溯类 Skill 体验有断点。

**第四是缺评测体系**。Skill 改了之后效果是好是坏只能靠用户反馈，没有量化指标，迭代效率低。

**优化方向**：
1. **业务知识库结构化做深**：每张核心表都自动生成知识文件并定期回写
2. **Skill 拆细 + 加评测**：引入小规模 case 集回归，每次 Skill 改动跑一遍看准确率
3. **推动平台侧补齐 MCP 工具**：把血缘、分区状态、跨平台调度这些高频动作都覆盖
4. **上下文窗口管理**：超长上下文场景做摘要 + 增量加载，避免噪声

> 💡 **专家补充**：
> - **AI Agent 落地的瓶颈往往不在模型而在"周边"**：知识库、工具链、评测体系——模型能力大家差不多，差距在于这些工程化基础是否扎实
> - **"评测体系缺失"是 AI 项目通病**：90% 的团队改 Prompt / Skill 都靠拍脑袋，没有量化指标。建立 case 集 → 回归测试 → 指标可视化，是从 demo 到生产的必经之路
> - **Skill 颗粒度的设计原则是"原子化 + 可组合"**：每个 Skill 只做一件事，复杂任务由多个 Skill 编排完成。这和软件工程的单一职责原则是一脉相承的
