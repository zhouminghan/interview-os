# 一句话

Schema 只描述数据怎么存，语义层描述业务怎么算；没有语义层，SQL 能跑通但数字一定算错。

# 30 秒回答

很多人以为把库表 Schema 丢给大模型、让它生成 SQL 就行。真正麻烦的不是 SQL 写不出来，而是 SQL 正常执行了、数字却算错了。业务问「上个月华东新客支付 GMV」，里面藏着一堆口径：上个月是自然月还是最近 30 天、华东按用户地区还是收货地区、新客按注册还是首单、GMV 用下单金额还是实付金额、退款扣不扣。这些答案 Schema 都不会告诉模型，Schema 只能说明有哪些表、字段是什么类型。语义层解决的是「业务到底应该怎么算」。

# 1 分钟回答

- 语义层明确三类规则：指标怎么算（金额字段、过滤状态、绑定哪个业务时间）
- 数据怎么关联（订单/支付/退款分别什么粒度，哪些能直接 Join，哪些必须先聚合，否则一对多会把金额算重）
- 查询有什么边界（哪些维度能下钻、谁能看明细、指标用哪个版本、数据更新到什么时间）
- 定位：RAG 帮模型找到规则，Text-to-SQL 根据规则生成 SQL，但规则本身不能让模型临时发挥
- 面试一句话记忆：Schema 管结构，语义层管口径
