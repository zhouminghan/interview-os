# 一句话

共享 State 加版本号做乐观并发，每个节点落 Checkpoint，恢复靠幂等键重放而不是从头跑。

# 30 秒回答

这题把 Agent 面拉回了分布式系统工程，正好是数据开发能发挥的地方。核心矛盾是多个 Agent 并发写同一份状态：要么用共享 State + 版本/字段级锁，要么用消息传递让状态归属单一。恢复时不能简单重跑，得靠幂等键和已提交记录跳过已完成步骤。

# 1 分钟回答

- State 设计：区分只读上下文、可写工作区、提交结果，避免所有 Agent 都能改同一块
- 并发控制：字段级乐观锁 / 版本号，冲突时按预设策略合并或转人工
- Checkpoint：在计划边界、工具调用前后、子任务完成时落盘，记录输入摘要与幂等键
- 幂等：每个副作用操作带 idempotency key，恢复时先查已提交记录再决定是否执行
- 避免竞争：把有冲突的资源收敛到单一 Owner Agent，其他 Agent 通过消息申请
- 恢复粒度：从最近成功 Checkpoint 续跑，已成功步骤不重放；重放要可证明无副作用
