> **来源面经**：阿里系-AI数据工程师两面-20260521 集团2-Q3

AI 数据工程师 = **传统数据工程师** + **AI 工程能力** + **业务上下文沉淀者**，三位一体。

**1. 传统数据工程师的底盘不能丢**
- 数仓建模、ETL 开发、SQL 优化、调度治理、数据质量——这些是地基
- AI 再怎么强大，**数据本身的质量和组织方式决定了 AI 的天花板**——脏数据 + 烟囱表 = AI 也救不了

**2. AI 工程能力是新增量**
- **Skill 工作流编排**：把高频数据开发场景固化成 SOP（建模、出库、回溯、知识生成）
- **MCP 接入**：把数据平台能力（建表、跑 SQL、查血缘、查分区状态）通过 MCP 协议暴露给 AI
- **知识库构建**：业务域、表元数据、指标口径、建模规范——作为 AI 的上下文
- **Prompt/上下文工程**：让 AI 输出符合团队规范的 SQL / DDL / 任务配置

**3. 业务上下文的沉淀者（最容易被忽略）**
- AI 时代**业务知识必须可被机器消费**——结构化的 wiki、表知识文件、指标注册中心比"老员工口口相传"更重要
- AI 数据工程师本质上是在**把组织的隐性知识显性化**，让团队具备 AI 杠杆能力

**与传统数据开发的差异**：

| 维度 | 传统 DE | AI 数据工程师 |
|------|---------|--------------|
| 角色定位 | 执行者（手写 SQL / 点平台按钮） | 方案审核者 + AI 编排者 |
| 核心产物 | 数仓表 + 报表 | 数仓表 + Skill + 知识库 |
| 业务交互 | 接需求 → 开发 → 交付 | 沉淀知识 → AI 自助生产 → DE 把关 |
| 价值创造 | 一对一服务业务方 | 一对多放大业务方自助能力 |

**回答模板**：「我理解 AI 数据工程师是**「数据底盘 + AI 增量 + 知识沉淀」**三位一体的角色——数仓建模和 SQL 是地基，Skill / MCP / 知识库是新增量工具链，本质是**让组织的隐性数据知识显性化、机器可消费**，从而把 DE 从执行者升维成方案审核者。」

> 💡 **专家补充**（大数据架构师视角，面试中视情况展开）
>
> - **「AI 数据工程师」不是「AI 应用工程师」也不是「数据科学家」**——前者偏算法应用调用，后者偏统计建模训练；AI 数据工程师的核心战场是**让数据生产链路本身被 AI 加持**，不是去训模型
> - **2025-2026 是 AI 数据工程师岗位真正落地的元年**——之前各家有"AI + 数据"的探索但没成型，今年随着 MCP 协议、Cursor/Claude Code 等 AI Coding Agent 成熟，岗位定义才稳定下来
> - **岗位 JD 看不出来的真相**：能不能落地 AI 数据工程师角色，**取决于公司数仓规范化程度**——规范越烂的公司 AI 越难赋能，因为 AI 没有可消费的知识源。所以这个岗位本质上倒逼数仓走向标准化
> - **能讲清「为什么 AI 数据工程师 ≠ 算法工程师」是面试加分点**——很多候选人会把这个岗位往算法方向解释，反而显得对岗位定位不清晰
