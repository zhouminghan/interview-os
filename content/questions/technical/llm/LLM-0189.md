# 一句话

六环节链路：问题理解 → 语义召回 → 查询生成 → 校验 → 执行 → 解释与反馈；模型是发动机，语义层是地图，校验是刹车。

# 30 秒回答

很多候选人一上来就讲「用大模型生成 SQL」，然后就没了，会被追问到崩：表那么多模型怎么知道用哪张？口径谁定？SQL 错了怎么办？数字对不对谁负责？面试官要看的是一套从问题理解到结果可信的完整链路。关键设计有三点：不让模型直接面对几千张物理表，而是面对精选的语义层；生成之后必须校验；结果必须可解释。

# 1 分钟回答

- 问题理解：意图分类（查数/解释/闲聊）、时间解析（上周=？）、实体识别（华东区/新客），信息不足则澄清
- 语义召回：从语义层召回候选指标/维度/枚举值 + 相似历史问答（few-shot）
- 查询生成：优先生成结构化查询（指标+维度+过滤），复杂问题再生成 SQL
- 校验：语法 / 权限 / 分区过滤 / 预估扫描量 / 口径一致性
- 执行：只读账号、超时、行数上限、结果缓存
- 解释与反馈：数字 + 图表 + 口径说明 + 生成的 SQL，用户点赞/纠错回流
- 评估：真实历史问题建评测集，按难度分层统计准确率，持续迭代

# 追问

- ②语义召回和④校验哪个更重要？为什么数据开发在这两个环节最能发挥价值？
- 权限怎么控制？不同业务能看到的数据范围不同怎么办？
- 成本怎么估？大模型 Token 成本和人工开发成本怎么对比？
