# 一句话

按链路逐段留痕：先看规划拆得对不对，再看工具选得对不对，再看参数，最后才看模型推理；每个 Bad Case 固化成评测用例防回归。

# 30 秒回答

没有全链路日志，Bad Case 只能靠猜。所以前提是每次运行都记录意图、计划、工具调用、入参、返回结果和最终答案的结构化轨迹。定位顺序从上游往下走，避免一上来就调 Prompt。

# 1 分钟回答

- 第一步 规划：任务拆解是否遗漏、顺序是否错、该澄清时有没有澄清
- 第二步 工具：是否选对、是否用了废弃版本、检索召回是否漏了正确工具
- 第三步 参数：字段、单位、时间范围、枚举是否合规，Schema 是否有歧义
- 第四步 推理：结果汇总是否偏离证据、有没有引用不存在的字段
- 回流：定位结论写成结构化标签，把该用例补进评测集并标注期望行为
- 防回归：发版前全量跑评测集，重点用例设为阻断项
- 修复优先级：能靠代码/规则修的，别靠改 Prompt 碰运气
