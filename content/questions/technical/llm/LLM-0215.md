# 一句话

看语料规模和复用度：文档多、要反复查、只需局部片段就上向量检索；文档少、要通读全局、一次性问答就直接塞进上下文。

# 30 秒回答

平安科技 09-08 一面原题。这题考的不是「向量库是什么」，而是能不能说出省略检索的边界条件，很多人会不假思索地答「都用 RAG」。

# 1 分钟回答

- 直接读文档：单篇或少量文档、能放进上下文窗口、需要跨章节综合/对比/统计、要求不漏细节（如合同全文审阅、一份财报问答）
- 直接读的优势：无召回损失、无切分导致的语义断裂、无索引一致性问题，答案可追溯性最好
- 向量库：语料量大且持续增长、单次只需相关片段、同一批知识要被高频复用、有权限/多租户过滤需求
- 向量库的价值：把每次请求的上下文成本从「全量」压到 Top-K，同时支持语义召回而非关键词匹配
- 中间路线：先按元数据/目录/时间做规则过滤缩小范围，再把命中文档整篇送入上下文，避免切碎
- 混合更常见：向量召回候选 + 关键词/BM25 兜底 + Rerank，再拼进上下文；纯向量在专有名词、编号上容易漏
- 成本账：向量库要付切分、Embedding、索引维护、一致性对账的工程成本，小语料不划算
- 判据一句话：语料装得下就整篇给，装不下才检索；要全局理解就别切，要局部定位才切
