我参与了 MCP Server 的工具定义和接口对接。以「字段级血缘查询」为例：

**inputSchema 设计**：
```json
{
  "name": "query_field_lineage",
  "description": "查询指定表的指定字段的上下游字段级血缘关系",
  "inputSchema": {
    "type": "object",
    "properties": {
      "table_name": {
        "type": "string",
        "description": "目标表名（全限定名：db.table）"
      },
      "field_name": {
        "type": "string",
        "description": "目标字段名"
      },
      "direction": {
        "type": "string",
        "enum": ["upstream", "downstream", "both"],
        "description": "查询方向：上游来源/下游去向/双向"
      },
      "depth": {
        "type": "integer",
        "default": 2,
        "description": "追溯深度（层级数），默认2层"
      }
    },
    "required": ["table_name", "field_name"]
  }
}
```

**输出格式**：
```json
{
  "field": "db.table.field_name",
  "lineage": [
    {
      "level": 1,
      "direction": "upstream",
      "source_field": "db.source_table.source_field",
      "transform": "SUBSTR(source_field, 1, 730)",
      "task_name": "etl_task_xxx"
    }
  ]
}
```

**边界情况考虑**：
- 表名不存在 → 返回明确错误码 + "表不在元数据系统中"
- 字段是计算字段（如 CASE WHEN 生成的）→ 血缘可能指向多个源字段，返回数组
- 血缘断裂（某层的上游任务没有解析信息）→ 标记 `"lineage_status": "incomplete"` 并告知断裂位置
- 深度过大导致结果爆炸 → 限制最大深度为 5，超出提示用户缩小范围
- 权限问题 → 跨域表的血缘可能没权限查看，返回 `"access_denied"` 而不是空结果
