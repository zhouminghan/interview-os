# 一句话

把「最新」变成可度量的 SLA：文档带版本与生效时间，变更触发增量更新，检索时按版本和时效过滤，过期内容拒答而非混用。

# 30 秒回答

字节 11-04 一面把这道题放在 Agent 板块的最后，是知识库类项目的必追题。多数人只答「定期重新灌库」，会被追问到口径冲突、增量更新、以及怎么知道哪些文档过期。

# 1 分钟回答

- 元数据：每条知识带来源、版本、生效时间、失效时间、责任人、所属业务域
- 变更驱动：上游文档/指标口径变更触发增量 upsert，按 ID 先删后插，避免新旧并存
- 全量兜底：定期重建索引并做抽样对账，识别漏更新的条目
- 检索约束：按业务域、版本、时间范围过滤，过期版本不参与召回
- 冲突处理：同一指标多版本共存时以生效版本为准，无法判定则澄清或拒答
- 可观测：刷新延迟、过期条目数、答错回溯到具体文档版本的链路
- 口径场景：指标口径变更要连带失效依赖它的历史问答与评测用例

# 追问

- 增量更新期间新旧数据同时在库怎么隔离？
- 怎么定义和监控知识库新鲜度 SLA？
