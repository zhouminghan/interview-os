# 一句话

靠「不凭空造 + 强制校验 + 可追溯 + 不确定就反问」四道防线，而不是靠模型自觉。

# 30 秒回答

幻觉在数据场景的后果比在问答场景严重得多——数字错了会直接驱动错误的经营动作。核心做法是让模型的活动边界收敛：只能用知识库里存在的表和字段；生成后必须过语法、权限、分区、扫描量、口径一致性校验；返回数字时必须同时给出用的哪个口径、什么时间范围、什么过滤条件，让业务能自己判断；不确定时必须反问业务，不允许自行脑补。

# 1 分钟回答

- 禁止幻觉：禁止使用知识库以外的表/字段，不确定的口径必须反问
- 前置校验：语法、字段合法性、数据类型、主键、分区规则、小文件与倾斜风险预判
- 执行边界：只读账号、超时、行数上限、结果缓存；高危操作人工审核卡点
- 可追溯：生成的 SQL、改动、对话记录全部落血缘，结论必须挂事实引用
- 结果解释：数字 + 图表 + 口径说明 + 生成的 SQL，支持下钻核对

# 追问

- 模型给出了一个数字，业务说不对，你怎么排查？
- 如何区分「口径理解错」和「数据本身有问题」？
- 幻觉能不能完全消除？不能的话怎么控制影响面？
