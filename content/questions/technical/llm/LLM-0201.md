# 一句话

按「路径是否可枚举」分工：流程确定、要可审计可重试的交给代码，需要判断和应变的交给模型。

# 30 秒回答

这题是 Agent 架构面的第一道分水岭，答不好后面全被动。很多人只说「Agent 更灵活」，那就被追问到崩。真正的判断标准是输入的多样性和错误代价：需求路径有限、每步结果要确定性复现的，Workflow 更稳；用户意图发散、需要临场选工具或改计划的，才值得上 Agent。落地常见做法是混合——主干用代码编排，把「分类、选路、参数补全、异常归因」这几个点交给模型。

# 1 分钟回答

- 用 Workflow 的场景：路径可枚举、SLA 严格、每步要幂等回放、审计要求高
- 用 Agent 的场景：意图发散、工具组合不确定、需要多轮澄清和自我修正
- 交给模型：意图分类、工具选择、参数补全、结果自检、失败归因
- 交给代码：权限校验、执行边界、超时重试、状态持久化、审批卡点
- 成本视角：Agent 每多一次模型调用就多一份延迟和 Token，稳定路径别浪费
- 面试加分：说明你在项目里哪些环节从 Agent 退回了 Workflow，为什么
