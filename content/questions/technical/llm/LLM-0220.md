# 一句话

先把窗口当预算按角色切块（系统指令、工具定义、记忆、检索、历史、输出预留），再把稳定前缀放最前面提高 prompt caching 命中；tool_call 与 result 必须成对，否则 API 直接报错或模型学到错误的交互模式。

# 30 秒回答

拼多多 11-04 五轮复盘里明确写「上下文管理准备工程方案，不是概念」。面试官要的是预算数字和截断策略，不是「做压缩」三个字。

# 1 分钟回答

- 预算切块：给系统指令、工具 schema、长期记忆、RAG 片段、对话历史、输出预留分别设上限，超限时按「可逆性」丢——先丢旧历史，最后才动指令和工具定义
- 输出预留：不把窗口填满，给最终答案和工具返回留足 token，否则容易在生成中途被截断
- 缓存命中：把不变的系统 Prompt、工具定义、少样本示例固定在最前面的稳定前缀，变动内容（用户输入、检索结果、历史）全部后置；前缀任何一个字节变了缓存就失效
- 常见破缓存：在 system prompt 里塞当前时间/随机 ID、动态重排工具列表、每次重新拼接示例顺序
- tool_call/result 成对：协议要求 assistant 的 tool_calls 后必须紧跟每个 tool_call_id 对应的 role=tool 消息，缺一个或顺序错会直接报错
- 压缩时的坑：截断历史若正好把某次 tool_call 留下、把它的 result 删掉，会话结构就坏了；压缩必须按「一轮交互」为最小单位，成对保留或成对删除
- 压缩手段：旧轮次摘要化、工具原始返回替换为结果摘要 + 可重查引用、超长文档改存外部只留指针
- 分层记忆：热记忆进上下文、温记忆进可检索库、冷记忆落存储按需召回，避免把全部历史硬塞进窗口
- 可观测：命中率、平均输入 token、压缩后信息丢失抽检（压缩前后同一问题答案一致性）
