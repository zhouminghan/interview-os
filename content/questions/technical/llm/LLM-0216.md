# 一句话

以源文档为唯一事实源，用稳定 chunk_id + 内容哈希做变更检测，走「先删后插」的幂等 upsert，再用定期全量对账兜住漏更新。

# 30 秒回答

10-16 AI 数据工程师面试题里的高频题（原帖标 88%）。难点不在写入，而在「文档改了/删了，索引里那份旧向量还在」，答不出删除与对账基本就挂了。

# 1 分钟回答

- 稳定标识：chunk_id = doc_id + 版本号 + 段落位置/内容哈希，禁止用随机 ID，否则无法判断是更新还是新增
- 变更捕获：文档系统发 CDC/事件，或定时比对 content_hash，只有哈希变化才重新 Embedding
- 删除必须显式：文档下线或段落合并时按 doc_id 批量删旧向量，很多不一致来自「只增不删」
- 先删后插：同一 chunk_id 的 upsert 要保证原子性，避免新旧两份向量并存造成召回重复或答案冲突
- 版本与生效时间：向量条目带 doc_version、valid_from/valid_to，检索时按版本过滤，灰度期间可隔离新旧
- 全量对账：定期用源文档清单与索引清单做 diff，统计孤儿向量、缺失 chunk、哈希不匹配三类差异
- 可观测：刷新延迟、积压队列长度、对账差异数设告警，答错时能回溯到具体文档版本
- 口径联动：Embedding 模型换版会影响向量空间，需整库重建或按模型版本分索引，不能混存
