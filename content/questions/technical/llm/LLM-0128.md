> **来源面经**：阿里系-AI数据工程师两面-20260521 集团1-Q5.4

Agent 问数主流是 Text-to-SQL，但**还有 4~5 条非 SQL 技术路线**，各有适用场景：

**路线 1：Text-to-API（语义路由到预定义指标 API）**

- **思路**：不让 AI 写 SQL，而是把常用指标封装成 API（如 `getDAU(date_range, dim)`），AI 选 API + 填参数
- **优点**：准确率高（因为 API 是人工写的）、延迟低（API 走预计算）
- **缺点**：覆盖率低（要事先定义 API）、灵活性差（新指标要先开发 API）
- **适用**：高频核心指标 + 准确率要求高的场景

**路线 2：Text-to-DSL（领域专用语言）**

- **思路**：定义一种比 SQL 简单的 DSL（如 LookML、Cube.js DSL），AI 输出 DSL 后再编译成 SQL
- **优点**：DSL 比 SQL 简单（指标和维度抽象层级更高），AI 出错率低；语义层统一保证口径一致
- **缺点**：要先建语义层（成本高）；DSL 表达力受限
- **适用**：有完善语义层的公司（Looker / Cube.js / 阿里 OneService）

**路线 3：Text-to-多模态（图表/可视化直出）**

- **思路**：AI 不输出 SQL 或 API，直接输出"图表配置 + 数据"——用户问"近 7 天 GMV 趋势"，AI 直接返回可视化图
- **优点**：用户体验好（不用看数字）；适合数据探索场景
- **缺点**：底层仍依赖 SQL/API；图表配置生成本身有不准确性
- **适用**：交互式数据分析产品

**路线 4：Text-to-工作流（多步任务编排）**

- **思路**：复杂问题不是一句 SQL 能答的（如"为什么本周 GMV 下降"），AI 拆解成多步：①查总 GMV ②按维度下钻 ③看异常维度 ④输出归因报告
- **优点**：能处理开放性归因问题
- **缺点**：链路长、容易累积误差；上下文要求高
- **适用**：根因分析、归因诊断、深度数据探索

**路线 5：RAG + 历史 SQL 召回**

- **思路**：不让 LLM 从零写 SQL，而是召回**历史相似问题的 SQL**，LLM 改写参数即可
- **优点**：准确率高（基于历史验证过的 SQL）；冷启动后越用越准
- **缺点**：依赖历史 SQL 积累；新问题覆盖不到
- **适用**：内部已有大量 SQL 沉淀的成熟数据团队

**对比小结**：

| 路线 | 准确率 | 覆盖率 | 实施成本 | 适用场景 |
|------|--------|--------|---------|---------|
| Text-to-SQL | 中 | 高 | 中 | 通用问数（主流方案） |
| Text-to-API | 高 | 低 | 中 | 高频核心指标 |
| Text-to-DSL | 中高 | 中 | 高 | 有语义层的成熟团队 |
| Text-to-多模态 | 中 | 中 | 高 | 可视化探索产品 |
| Text-to-工作流 | 中低 | 高 | 高 | 归因诊断 |
| RAG + 历史 SQL | 高 | 中 | 低 | 内部 SQL 多的团队 |

**回答模板**：「主流是 Text-to-SQL，但其实有 4~5 条路线可以选——**Text-to-API**（高频指标走预定义 API）、**Text-to-DSL**（基于语义层走 LookML/Cube.js 这种 DSL）、**Text-to-多模态**（直接出图表）、**Text-to-工作流**（复杂归因走多步编排）、**RAG + 历史 SQL 召回**（用历史验证过的 SQL 复用）。生产上往往是**多路线混合**——核心指标走 API、长尾查询走 SQL、归因诊断走工作流。」

> 💡 **专家补充**（大数据架构师视角，面试中视情况展开）
>
> - **生产 Agent 问数系统不会单一路线打天下**——通常是「**多路线 Router**」架构：一个意图识别模型根据问题类型路由到 Text-to-API / Text-to-SQL / Text-to-工作流不同 pipeline
> - **Text-to-DSL 在 2025 年开始崛起**——dbt + Cube.js 这套语义层方案越来越成熟，AI 基于语义层比直接写 SQL 准确率高得多。这是大型团队的最优解
> - **「Text-to-工作流」是最有想象空间但也最不成熟**——能解决开放性根因分析问题，但当前成功率低（链路长 + 误差累积）。这是 2026 年值得关注的方向
> - **回答这题的加分项是「分场景选型」**——光列路线像背书，能给"什么场景用什么路线"才显示出工程判断力
