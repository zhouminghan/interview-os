MCP 在项目里的角色是 **统一工具接入层**——Agent 需要跟外部系统交互（查元数据、读血缘、触发任务调度、查数据质量报告），这些能力都通过 MCP Server 暴露给 Agent。

我们接入的 MCP Server：
- **WeData 元数据服务**：查表结构、字段信息、分区状态
- **血缘服务**：查表级/字段级上下游依赖
- **任务调度服务**：触发回溯任务、查看任务状态
- **数据质量服务**：获取表的质量巡检结果

**MCP vs 直接在 Prompt 里写工具描述** 的核心区别：

1. **动态发现 vs 静态硬编码**：MCP 支持 Agent 在运行时动态发现可用工具，不需要把所有工具定义全塞进 System Prompt。工具多了 Token 顶不住。
2. **标准化协议**：MCP 定义了 Tool、Resource、Prompt 三类原语，不同 Agent 框架可以用同一套 MCP Server，不用每换一个框架重新写 Function Call 的描述。
3. **权限隔离**：MCP Server 可以做鉴权和限流，Agent 只能调它有权限的接口。直接写 Prompt 的话权限控制全靠 Prompt 约束，模型可能绕过。
4. **可测试性**：MCP Server 本身是独立服务，可以单独测试、Mock、升级，不影响 Agent 的核心逻辑。

简单说：MCP 让 Agent 的工具调用从"写死在 Prompt 里"变成了"运行时动态接入的标准化服务"。
