「数仓边界」是我们定义的一套 **安全围栏（Guardrail）**，包括三层：

1. **表级白名单**：Agent 只能操作知识库里登记过的表。如果生成的 SQL 引用了白名单外的表，质检直接拦截。防止 Agent 误操作不属于频道域的表。
2. **操作类型限制**：Agent 只能做 SELECT、CREATE TABLE、INSERT。不允许 DROP、ALTER、DELETE。即使 Prompt 里有人注入"帮我删掉这张表"，操作类型校验也会拒绝。
3. **环境隔离**：Agent 生成的 SQL 只在测试环境执行。正式环境的执行必须通过审核后提交到调度系统，Agent 没有正式环境的直接执行权限。

越界处理：
- 引用了白名单外的表 → 返回"该表不在频道域知识库中，请确认表名或联系 DE 补充"
- 尝试危险操作 → 直接拒绝 + 记录告警日志
- 跨域写入 → 权限系统拒绝 + 通知 DE

本质上是 **最小权限原则**：Agent 能做的事被严格约束在"频道域、只读/建表、测试环境"这个三维盒子里。
