> **来源面经**：阿里系-AI数据工程师两面-20260521 集团2-Q7.3

**MCP（Model Context Protocol）和 Skill 是两个不同层级的东西，不是替代关系而是协作关系**。

**一句话区分**：
- **MCP = AI 与外部系统交互的「协议层」**（横向、底层）
- **Skill = AI 完成特定任务的「工作流层」**（纵向、上层）

**详细对比**：

| 维度 | MCP（Model Context Protocol） | Skill |
|------|------------------------------|-------|
| **定位** | 标准化协议（类比 HTTP） | 业务工作流（类比 RESTful API） |
| **解决问题** | AI 怎么和外部系统通信 | AI 怎么完成具体业务任务 |
| **抽象级别** | 底层（工具调用接口标准） | 上层（任务 SOP 编排） |
| **来源** | Anthropic 2024 年提出的开源协议 | 各 AI 平台/团队自定义（CodeBuddy / Claude Code / Cursor） |
| **可移植性** | 跨工具、跨平台（标准化） | 与 AI 平台绑定（Skill 格式不通用） |
| **维护方** | 平台/基建团队提供 | 业务/应用团队编写 |
| **典型例子** | 「查 Hive 表元数据」MCP 工具 | 「数据回溯 Skill」编排多个 MCP 工具完成回溯 |

**一个具体例子（项目里的真实情况）**：

我们的「数据回溯」是一个 Skill，它**调用了多个 MCP 工具**：

```
Skill: 数据回溯 SOP
  ├── 步骤1: 调用 MCP 工具「查血缘」获取上游依赖
  ├── 步骤2: 调用 MCP 工具「查分区」批量检查上游表分区状态
  ├── 步骤3: LLM 推理生成回溯计划
  ├── 步骤4: DE 审核
  └── 步骤5: 调用 MCP 工具「触发任务」批量发起回溯
```

**MCP 工具**由平台侧同事提供（基建能力），**Skill** 由我编排（业务工作流）。一个 Skill 通常调用 3~10 个 MCP 工具，MCP 工具的数量级是几十个，Skill 的数量级是几个。

**回答模板**：「MCP 是**协议层**像 HTTP，定义 AI 怎么调外部工具；Skill 是**工作流层**像业务接口，定义 AI 怎么完成一个具体任务。我项目里的数据回溯 Skill 调用了**查血缘、查分区、触发任务**等多个 MCP 工具——MCP 是基建团队提供的能力，Skill 是我们编排的业务 SOP。」

> 💡 **专家补充**（大数据架构师视角，面试中视情况展开）
>
> - **2024 年 11 月 Anthropic 提出 MCP 是个里程碑事件**——之前每个 AI 平台都有自己的 Function Calling 格式（OpenAI 一种、Anthropic 一种、Google 一种），MCP 把它标准化了，类似 HTTP 之于 Web 的地位
> - **MCP 的杀手级特性是「工具一次接入、所有 AI 平台可用」**——同一个 MCP Server 可以同时被 Claude Code / Cursor / CodeBuddy 调用，不用重复对接。这极大降低了平台 lock-in
> - **「Skill 不通用」是 MCP 解决不了的问题**——Skill 格式跟具体 AI 平台耦合（CodeBuddy 的 Skill 格式 ≠ Claude Code 的 Slash Command 格式），换平台还是要重写 Skill。这是当前生态的痛点
> - **回答这题的高分姿势是「分层 + 协作 + 项目案例」**——很多候选人把 MCP 和 Skill 对立讲（"用 MCP 还是用 Skill"），反而暴露理解不到位。能讲清楚两者的协作关系是面试官想听到的
