# 一句话

80% 之后瓶颈不在模型，在语义层覆盖度、评测集建设和纠错回流闭环。

# 30 秒回答

先要承认 80% 到 95% 的难度远大于 0 到 80%：前面靠模型能力，后面靠数据工程。抓手主要在四处——把高频问不到的问题补进语义层；建设分层评测集，按难度统计准确率而不是只看整体；对模型不确定的问题主动澄清或拒答，用「不会」换「不错」；把用户纠错和点赞回流进评测集做持续迭代。

# 1 分钟回答

- 语义层补覆盖：从线上真实问题里挖未覆盖的指标/维度/枚举值，优先补 Top N
- 评测集建设：用真实历史问题建集，按难度分层（单指标 / 多指标 / 跨周期 / 比率类）分别统计准确率
- 澄清与拒答：意图置信度低时反问（如「复购率按 30 日还是自然月？」），宁可少答也不错答
- 检索增强：召回相似历史问答做 few-shot，比单纯堆 Schema 有效
- 闭环迭代：答错 + 用户纠正的问题自动进评测集，版本发布前回归

# 追问

- 两个 SQL 写法不同但结果相同，判定为对还是错？
- 如何防止为了冲准确率而过度拒答？
