# 一句话

Agent 完成探查、规则生成、异常溯源；难点在业务理解不足、元数据依赖强、计算成本高，只能做辅助巡检，结论需人工确认。

# 30 秒回答

传统数仓数据质量靠人工写规则、看告警，规则维护成本高。Agent 可以接入元数据、血缘和监控指标，自动探查表、生成质检规则、对比历史基线识别异常、顺着血缘定位根因。但它解决不了「业务正常波动」和「数据异常」的区分问题，所以只能做辅助。

# 1 分钟回答

- 四个任务：自动探查（空值、极值、字段分布、主键重复率）、规则推理（按业务含义生成质检规则）、异常识别（对比基线识别突增突降和分布漂移）、根因定位（顺血缘追溯源表/CDC/埋点）
- 适用场景：离线 Hive 表、实时 DWD/DWS 层周期性质检，自动生成质检报告
- 难点一：业务理解门槛高，容易把正常波动判成异常，产生告警风暴
- 难点二：元数据不准时，血缘和表注释缺失会让根因推理跟着错
- 难点三：频繁抽样跑探查 SQL，大表扫描消耗大量计算资源
- 难点四：无法替代人工决策，业务变更、版本灰度这类人为变更它判断不了
- 管控方案：硬规则（非空、主键唯一）交给 Agent 自动执行；业务相关软阈值只预警、人工复核；Agent 只读抽样数据，禁止全表扫描
