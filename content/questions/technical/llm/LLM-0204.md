# 一句话

MCP 封装的关键不是包一层协议，而是把接口描述成模型能稳定理解、能判错、能回滚的契约。

# 30 秒回答

面试官问这个，是想确认你真的接过企业内部系统，而不只是调过公开 MCP Server。重点在四件事：Schema 要让模型填得对（字段名、枚举、必填、示例），错误信息要让模型知道下一步该改参数还是该放弃，流式返回要区分增量事件与最终结果，兼容性要考虑工具版本演进不能让老 Agent 突然失效。

# 1 分钟回答

- Schema：语义化命名 + 明确必填/可选 + 枚举约束 + 单位与时间格式 + 一两个 few-shot 示例
- 错误信息：区分参数错误（可重试）、权限不足（转人工）、下游超时（重试或降级），给可操作的提示
- 流式返回：增量事件带序号与阶段标记，最终结果单独一条并带完整状态，避免模型把中间片段当结论
- 兼容性：工具名与参数只增不删，废弃走 deprecated 标记 + 过渡期，版本写在元数据里
- 安全：只读与写操作分开暴露，写操作绑定审批和幂等键
- 可观测：记录每次调用的入参摘要、耗时、错误码，作为 Bad Case 归因依据
