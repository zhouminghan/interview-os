| 比较维度 | Hadoop MapReduce | Apache Spark |
|---|---|---|
| 成本效益 | 需要大量服务器、存储和数据中心，安装和使用昂贵 | 成本效益高的解决方案 |
| 性能 | 处理速度相当慢（基于磁盘） | 比 Hadoop MapReduce 快 10-100 倍（内存处理） |
| 开发易度 | 支持多种工作负载但开发较复杂 | 在同一应用中结合流、SQL、机器学习，更容易开发 |
| 故障恢复 | 通过写入磁盘实现容错 | 通过 RDD 血缘实现容错恢复 |
| 文件系统 | 自有 HDFS | 需与 HDFS 等集成 |
| 计算模型 | 批处理 | 微批处理（近实时） |
| 代码行数 | ~2300 万行 | ~2 万行 |
| 缓存 | 无缓存机制 | 支持内存缓存 |
| 调度器 | 需要外部调度器（如 Oozie） | 自有作业调度器 |
| API | 底层 API，不够灵活 | 高级 API，更高效 |
| 窗口条件 | 不支持流处理，无窗口 | 支持基于时间的窗口 |
| 延迟 | 高 | 低（内存计算） |
| 内存管理 | 静态或动态 | 自动内存管理系统 |
| 迭代处理 | 不支持 | 支持迭代处理 |
| 许可证 | Apache 2.0 | Apache 2.0 |
