# 一句话

流程是「采集执行计划与指标 → 归因定位 → 生成优化建议 → 灰度验证 → 沉淀规则」；分析不到位的地方靠规则库和人工复核补，成熟部分固化成 SOP。

# 30 秒回答

这题考的是你有没有把 AI 用进实际调优工作，而不是只会聊天。真实流程：把 Spark 的 SQL、执行计划、Stage 指标、数据倾斜特征喂给模型做归因，让它给出参数或 SQL 改写建议，然后在测试环境灰度验证效果，验证通过的沉淀为规则。AI 分析不到位的部分（如业务语义导致的特殊逻辑）需要人工补位。

# 1 分钟回答

- 输入：SQL、执行计划、Stage/Executor 指标、倾斜特征、历史运行基线
- AI 归因：判断是倾斜、小文件、并行度不足、广播选择不当还是资源问题
- 生成建议：参数调整（并行度、executor、shuffle 分区）、SQL 改写、Join 策略（broadcast / salt / map join）
- 灰度验证：测试环境对比优化前后的运行时长和资源消耗
- 沉淀：验证有效的优化沉淀为规则和 SOP，未通过的人工分析后补充规则库
- 局限：AI 看不懂业务语义导致的特殊逻辑，这类必须人工介入
- SOP 化：把高频问题类型 → 检查项 → 优化动作的映射固化，AI 只做初筛
