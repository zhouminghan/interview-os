# 一句话

MapReduce 是「Map + Reduce」两阶段计算模型；因为中间结果全落盘、多作业靠 HDFS 串数据（带副本），慢且 IO 重，逐步被 Spark 的内存计算 + DAG 取代。

# 30 秒回答

Map 做映射、Shuffle 分区、Reduce 做聚合。慢的原因：map 输出落盘、shuffle 落盘、reduce 输出写 HDFS，多个 MR 之间通过 HDFS 传递且带副本。Spark 用内存计算 + DAG pipeline 少落盘，所以快一个量级。

# 1 分钟回答

- 编程模型：Map（映射/过滤）+ Reduce（聚合），中间靠 Shuffle 按 key 分组
- 为什么慢：中间结果全落磁盘，复杂作业拆多个 MR，数据通过 HDFS 传递还带 3 副本
- Spark 替代点：内存计算、DAG 同 Stage 内 pipeline、算子丰富（不止 Map+Reduce）
- 价值：MR 的「分而治之 + Shuffle」思想是 Spark/Flink 的基础
- 现在：Hive on Spark，Hive 做解析元数据，Spark 做实际执行
