# 一句话

会出现数据倾斜：少数大 key 让个别 task/reducer 负载过重，形成长尾。

# 30 秒回答

单 key 数据量过大时，group by 或 join 会把大量数据分到同一个 task，导致该任务耗时远超其他任务、内存溢出 OOM、任务卡住甚至失败。

# 1 分钟回答

- 负载不均：个别 reducer 处理量是其他的几十倍
- 长尾：整体任务被最慢的那个 task 拖住
- OOM：单 task 内存装不下大 key 数据
- 资源浪费：其他 task 早已空闲，集群利用率低
- 与 SQL-0003 呼应：这是优化要解决的根因
