# 回答思路

1. 开口先问清题目要的指标和结果粒度，不急着把 Project、Employee、Department、Budget 四张表直接连起来。
2. 接着画关联关系并确认每步基数：Project 与 Employee 是否多对多，Employee 属于哪个 Department，Budget 是按部门还是按项目记录。
3. 然后先过滤、先聚合到连接粒度，再用明确的 `ON` 条件逐层 JOIN，避免金额被重复累加。
4. 最后说明 `LEFT JOIN` 与过滤条件的放置，并给出按 key 检查行数的验证办法。

# 一句话

四表 JOIN 的重点不是写出连接语法，而是先确定结果粒度，把每张表收缩到该粒度后再关联，防止行数膨胀和预算重复计算。

# 30 秒回答

我会先问最终一行代表什么，是一个项目、一个员工，还是部门加月份。然后再看 Employee 到 Department 是不是一对多，Budget 又落在哪个粒度。如果预算表比结果粒度更细，就在子查询里先聚合；如果项目与员工是多对多，也要先确认桥接键。关联前把每侧的行数按 key 核一下，比事后发现总额翻倍更稳。

# 1 分钟回答

第一，确定目标粒度和关联链：写出每个 CTE 的主键，标清 Project、Employee、Department、Budget 之间是一对一、一对多还是多对多，不能凭表名猜字段。第二，按粒度处理数据：先用 `WHERE` 收窄时间范围，再把预算聚合到部门/期间或项目/期间，最后才连员工和项目维度；聚合后的 CTE 每个连接键只留一行。第三，补边界与验证：内连接可把过滤放 `WHERE`，但 `LEFT JOIN` 的右表条件应放 `ON`，否则会意外变成内连接；每加一个 JOIN 都按 key 比较连接前后行数和金额总和，有重复键时先去重，不要靠最终 `DISTINCT` 掩盖膨胀。

# 追问

- 预算金额被放大，通常是什么原因？回答要点：Budget 的粒度比目标结果更细，或关联键有多行；应先把预算聚合到目标粒度，再做一对一连接。
- `LEFT JOIN` 的右表过滤写在哪里？回答要点：写在 `ON` 中才能保留左表未匹配行；写到 `WHERE` 会把 NULL 行过滤掉，使结果接近 `INNER JOIN`。
- 怎样快速定位 JOIN 后的错误？回答要点：分阶段统计每个 CTE 的连接键去重数和行数，再比较 JOIN 前后的行数与指标总和，定位第一次发生膨胀的步骤。
