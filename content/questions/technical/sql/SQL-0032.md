# 回答思路

1. 开口先问清比较口径：结果是否要求行顺序一致，重复行算不算差异，NULL 和数值类型如何判定。
2. 接着把两段结果放在同一数据快照、同一参数和同一时区/排序规则下执行，排除环境差异。
3. 然后先用双向差集找不同行，再按整行计数检查重复行，避免只看截图或行数。
4. 最后排查 `LIMIT` 无稳定排序、非确定性函数和浮点/时间类型，这些会让等价 SQL 看起来不一致。

# 一句话

对比两段 SQL 的结果，先统一比较口径和执行环境，再用双向差集加重复行计数定位差异。

# 30 秒回答

我不会先盯着两张结果截图看。先确认业务上是否关心顺序和重复，再让两条 SQL 在同一份数据、同一时区和同一参数下跑。无序结果可以用双向 `EXCEPT` 找只在某一边出现的行；如果重复行也有意义，还要按所有列分组比较次数。最后再检查 `LIMIT`、随机函数和类型转换，很多差异其实来自口径没有对齐。

# 1 分钟回答

第一，定义结果：把两段 SQL 包成 CTE，确定业务主键或全列作为比较键；如果顺序属于结果语义，就加 `ROW_NUMBER()` 一起比，否则先稳定排序再展示。第二，做落地校验：用 `(A EXCEPT B) UNION ALL (B EXCEPT A)` 查不同的值，再对整行做 `GROUP BY` 和 `COUNT(*)` 比较出现次数；支持 `EXCEPT ALL` 的引擎可以直接保留重复，普通 `EXCEPT` 往往会去重。第三，处理边界：`EXCEPT`/分组会把 NULL 视作同一组，不要用普通 `=` 逐列比较；两段 SQL 若含 `LIMIT` 而无确定性 `ORDER BY`、当前时间或随机数，需要固定输入后再比较，并结合执行计划确认差异是否来自过滤/JOIN 语义。

# 追问

- 为什么差集要跑两个方向？回答要点：`A EXCEPT B` 只能找到 A 多出的行，另一个方向才能找出 B 多出的行，合起来才是完整差异。
- 重复行怎么比较？回答要点：普通 `EXCEPT` 可能去重，应按全列分组比较计数，或在支持 `EXCEPT ALL` 的引擎中保留重复次数。
- 两段 SQL 看起来等价却偶发不同，先查什么？回答要点：优先检查无稳定排序的 `LIMIT`、随机/当前时间函数、NULL 比较、时区与浮点类型，并确认两边读取的是同一数据快照。
