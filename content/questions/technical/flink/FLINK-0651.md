**延迟定义**：从事件实际发生时刻（event_time）到指标在报表/Redis 中可查询的时间差。

**延迟拆解**：

| 环节 | 耗时 | 说明 |
|------|------|------|
| 日志采集 → Kafka | ~30s | 客户端上报 + 采集服务处理 |
| Kafka → Flink DWD | ~10s | Flink 实时消费 |
| Flink DWD → Iceberg commit | ~60s | 等一个 Checkpoint 周期 |
| Spark 聚合任务 | ~3-5min | 10 分钟调度 + 实际执行 2-3 分钟 |
| 写入 Redis / DataTalk | ~30s | Spark 写出 |
| **端到端 P50 延迟** | **~5-6 分钟** | 数据在调度窗口后半段产生时可较快处理 |
| **端到端 P99 延迟** | **~10 分钟** | 数据在窗口刚开始时需等满一个调度周期 |

**瓶颈**：Spark 聚合任务的调度间隔（10 分钟）是最大贡献者。注意 10 分钟是 P99 上界——如果数据在调度窗口开始后立即产生，需等完整 10 分钟才能被下一轮处理，所以"控制在 10 分钟以内"指的是 P99 ≤ 10min。如果未来需要进一步降低 P99 延迟，方向是用 Flink 直接做 DWS 聚合 + 写 Redis，可以做到秒级。当前 P99=10min 对业务够用，成本更低。
