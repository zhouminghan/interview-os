**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

> 控制在2分钟

提高复用率的关键是让人**找得到、看得懂、用得放心**。

**四个抓手：**

1. **数据地图** — 让资产可被发现（搜索/浏览/推荐）
2. **元数据标注** — 让资产可被理解（中文注释/字段含义/口径说明）
3. **质量保障** — 让人用得放心（有监控/有SLA/有负责人）
4. **推广机制** — 新建公共表主动推送给潜在使用者

**反面操作（降低复用率的事）：**
- 表命名没规范，搜不到
- 没有文档，看不懂字段含义
- 没有质量监控，数据经常出错，用户不敢用
- 没有血缘关系，不知道有现成表可用

**结合项目：** QQ频道通过数据地图建设+元数据标注后，新需求"先查有没有现成表"的习惯建立起来，{需要补充：复用率提升数据}。

**四、技术知识补充**

**项目结合点：** 回答时务必结合QQ频道实际场景，体现"不是背八股，是真做过"的信号。

**五、追问预判**

1. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

2. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。

3. **追问：这个方案的边界/不适用场景是什么？**
   → 任何方案都有适用范围，说清楚什么时候不应该用这个方案。


**六、常见错误/踩坑提醒**

- ❌ 只背分层定义不说为什么 → ✅ 每层说清楚解决什么问题
- ❌ 照搬电商方案不区分业务 → ✅ 强调社交业务的特殊性（维度变化快）
- ❌ 不提治理 → ✅ 4年经验必须体现架构+治理双视角

**七、记忆版（20秒压缩）**
