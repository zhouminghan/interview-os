**一、面试官真正想考什么？**

不是让你背定义，考的是**实操经验和问题解决能力**：
- 你是否有真实的动手经验
- 你能否讲清楚具体的做法和效果
- 你对这个问题的理解深度

**二、回答思路**

先给结论 → 展开核心要点（不超过3个）→ 结合项目经验 → 适用边界

**三、参考答案（面试标准版）**

| | Driver | Executor |
|---|---|---|
| 职责 | 解析用户代码、生成DAG、划分Stage、调度Task | 执行Task、缓存数据、向Driver汇报状态 |
| 数量 | 1个/Application | 多个/Application |
| 失败影响 | Application失败 | 对应Task重试 |
| 内存用途 | 广播变量、累加器 | 计算+数据缓存 |

**常见问题：**
- Driver OOM：通常是collect()返回数据太大或广播变量太大
- Executor OOM：Shuffle数据或缓存数据超出内存

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

2. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。

3. **追问：这个方案的边界/不适用场景是什么？**
   → 任何方案都有适用范围，说清楚什么时候不应该用这个方案。


**六、常见错误/踩坑提醒**

- ❌ 直接说调参数 → ✅ 先通过Spark UI定位问题类型，再针对性优化
- ❌ 不区分倾斜类型 → ✅ Join倾斜/聚合倾斜/分区不均方案不同
- ❌ 忽略全链路影响 → ✅ 优化一个环节可能影响下游（如增加分区→小文件）

**七、记忆版（15秒压缩）**

> Driver=大脑（调度），Executor=双手（执行）。Driver一个，Executor多个。Driver挂=全挂，Executor挂=Task重试。
