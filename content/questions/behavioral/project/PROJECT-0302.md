**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

分层设计：

**第一层：原子指标**
- 订单量、退货量、投诉量、评分、发货时长

**第二层：复合指标**
- 退货率 = 退货量/订单量
- 投诉率 = 投诉量/订单量
- 准时发货率 = 准时发货量/总发货量

**第三层：综合评分**
```text
商家健康度 = f(经营指标, 信誉指标, 合规指标)
  经营(40%): 销量增长率 + 活跃度
  信誉(40%): 退货率 + 投诉率 + 评分
  合规(20%): 违规次数 + 资质完整度
```

**阈值设计：**
- 健康：综合分 > 80
- 预警：60-80（触发关注）
- 风险：< 60（触发处置流程）

**四、技术知识补充**

**项目结合点：** 虽然之前做社交业务，但治理/建模方法论可迁移，重点讲方法论通用性。

**五、追问预判**

1. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

2. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。

3. **追问：这个方案的边界/不适用场景是什么？**
   → 任何方案都有适用范围，说清楚什么时候不应该用这个方案。


**六、常见错误/踩坑提醒**

- ❌ 说"我没做过商家业务所以不懂" → ✅ 治理逻辑通用：数据发现问题→触发动作→验证效果
- ❌ 只讲技术不结合业务 → ✅ 把QQ频道的治理经验迁移到商家场景
- ❌ 不讲方法论迁移 → ✅ 强调分层/建模/治理方法论跨业务复用

**七、记忆版（15秒压缩）**
