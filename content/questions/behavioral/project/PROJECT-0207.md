**一、面试官真正想考什么？**

不是让你背定义，考的是**实操经验和问题解决能力**：
- 你是否有真实的动手经验
- 你能否讲清楚具体的做法和效果
- 你对这个问题的理解深度

**二、回答思路**

先给结论 → 展开核心要点（不超过3个）→ 结合项目经验 → 适用边界

**三、参考答案（面试标准版）**

和Q31内容高度相关，侧重点不同——这题更强调**运行时全链路**：

```text
1. 客户端提交SQL → Hive Server2
2. 编译优化 → 生成DAG执行计划
3. 提交到YARN → Application Master启动
4. AM申请Container → 启动Executor/Task
5. 数据读取 → HDFS Scan（分区裁剪/列裁剪）
6. Map阶段 → 本地计算（过滤/投影）
7. Shuffle阶段 → 数据重分布
8. Reduce阶段 → 聚合/Join/排序
9. 结果写回HDFS或返回客户端
```

**关键瓶颈点：** ③资源等待、⑤数据读取量、⑦Shuffle数据量——这三个是优化最常切入的地方。

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：Hive和Spark SQL有什么区别？→ Hive底层是MR（慢），Spark SQL底层是DAG（快），但Hive MetaStore两者共用。**

2. **追问：AI生成的SQL出错了谁负责？→ 人负责。AI辅助生成，人Review确认，最终质量由人把关。**

3. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。


**六、常见错误/踩坑提醒**

- ❌ 只说优化手段不说定位过程 → ✅ 先定位瓶颈（EXPLAIN/执行计划），再选方案
- ❌ 优化没有量化效果 → ✅ 必须说"从X降到Y，提升Z%"
- ❌ 把所有优化手段堆上来 → ✅ 针对具体问题选最合适的方案

**七、记忆版（15秒压缩）**

> 提交→编译优化→申请资源→Map(读数据)→Shuffle(重分布)→Reduce(聚合)→输出。三大瓶颈：资源等待、IO量、Shuffle量。
