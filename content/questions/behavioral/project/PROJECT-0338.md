**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

数据事故处理SOP：

```text
1. 发现告警 → 5分钟内响应
2. 快速定位 → 确定影响范围（哪些表/哪些下游/哪些业务方）
3. 临时止损 → 暂停下游任务避免错误扩散/通知业务方
4. 根因分析 → 定位具体原因
5. 修复回溯 → 修复逻辑 + 数据回溯 + 验证
6. 通知恢复 → 通知业务方数据恢复
7. 复盘改进 → 5Why分析根因 → 防范措施
```

**关键原则：** 先止损再修复。不要在找原因的时候让错误数据继续传播。

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

2. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。

3. **追问：这个方案的边界/不适用场景是什么？**
   → 任何方案都有适用范围，说清楚什么时候不应该用这个方案。


**六、常见错误/踩坑提醒**

- ❌ 只关注开发不关注运维 → ✅ 数据工程包括开发+调度+监控+运维全链路
- ❌ 不讲数据质量 → ✅ 数据工程的核心产出是"可信的数据"
- ❌ 不提自动化 → ✅ 重复工作应该自动化（监控/告警/回溯）

**七、记忆版（15秒压缩）**

> SOP：响应→定位影响→止损(暂停下游)→找根因→修复回溯→通知恢复→复盘。原则：先止损再修复。
