**一、面试官真正想考什么？**

不是让你背定义，考的是**实操经验和问题解决能力**：
- 你是否有真实的动手经验
- 你能否讲清楚具体的做法和效果
- 你对这个问题的理解深度

**二、回答思路**

先给结论 → 展开核心要点（不超过3个）→ 结合项目经验 → 适用边界

**三、参考答案（面试标准版）**

> 控制在2分钟

五种方案按场景选择：

| 方案 | 原理 | 适用场景 |
|------|------|---------|
| AQE SkewJoin | 自动拆分大分区 | 通用，首选 |
| Broadcast Join | 小表广播避免Shuffle | Join一侧可放内存 |
| Salting（加盐） | 热点Key打散 | Join两侧都大 |
| 两阶段聚合 | 先局部聚合再全局聚合 | GroupBy场景 |
| 热点Key隔离 | 热点Key单独逻辑处理 | 极端倾斜 |

**选择优先级：**
1. 先开AQE（零成本）
2. AQE不够 → 判断是Join还是GroupBy
3. Join场景 → 一侧小用Broadcast，两侧大用Salting/隔离
4. GroupBy场景 → 两阶段聚合

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

2. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。

3. **追问：这个方案的边界/不适用场景是什么？**
   → 任何方案都有适用范围，说清楚什么时候不应该用这个方案。


**六、常见错误/踩坑提醒**

- ❌ 直接说调参数 → ✅ 先通过Spark UI定位问题类型，再针对性优化
- ❌ 不区分倾斜类型 → ✅ Join倾斜/聚合倾斜/分区不均方案不同
- ❌ 忽略全链路影响 → ✅ 优化一个环节可能影响下游（如增加分区→小文件）

**七、记忆版（20秒压缩）**

> 五方案：AQE(首选零成本)→Broadcast(小表)→Salting(两大表Join)→两阶段聚合(GroupBy)→热点隔离(极端)。先开AQE，不够再选。
