> **要点提纲**：业务知识库覆盖度 | Skill 颗粒度 | MCP 工具链 | 评测体系缺失 | 三个优化方向
> **来源面经**：字节-AI Agent数据开发一面-20260412 Q1
> **回答策略**：诚实承认半自动化阶段，给出系统化归因和明确优化路径，体现工程师思维

我们这套 AI + 数据工程体系目前还在半自动化阶段，效果差主要有几个原因：

**第一是业务知识库覆盖度不够**——频道有几百张表、几十个业务域，目前只沉淀了核心域的表知识文件，AI 在涉及非核心域时容易"幻觉"，字段命名不规范、分区字段写错。

**第二是 Skill 颗粒度太粗**——比如建模 Skill 一上来就让 AI 生成完整 SQL，但实际业务规则太复杂，应该拆成"识别建模模式 → 选择模板 → 填充参数"几步，让人在中间能干预。

**第三是 MCP 工具链不完整**——平台侧目前提供的 MCP 工具集中在元数据查询和任务创建，像血缘解析、分区状态批量查这些核心能力还在补齐，导致回溯类 Skill 体验有断点。

**第四是缺评测体系**——Skill 改了之后效果是好是坏只能靠用户反馈，没有量化指标，迭代效率低。

**后续优化方向有三个**：
1. 把**业务知识库结构化做深**，每张核心表都自动生成知识文件并定期回写
2. **Skill 拆细 + 加评测**，引入小规模 case 集回归，每次 Skill 改动跑一遍看准确率
3. 推动**平台侧补齐 MCP 工具**，把血缘、分区状态、跨平台调度这些高频动作都覆盖到

> 💡 面试要点：诚实 + 系统化归因 + 明确路径 = 比"包装得很完美"更让面试官信服。AI 项目本来就是探索期，承认不完美再讲怎么改，体现的是工程师思维。
