**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

> 控制在2分钟

虽然我之前做的是社交业务（QQ频道），但建模方法论是通用的。商家治理数仓的主题域，我会从业务过程出发：

**主题域划分：**
1. **商家基础域** — 商家基本信息、资质、经营范围
2. **交易域** — 商家交易行为（订单/金额/退货）
3. **行为域** — 商家平台行为（活跃/操作/违规动作）
4. **评价域** — 用户对商家的评价、投诉
5. **治理域** — 处罚记录、整改状态、风险标签

**设计方法：**
- 每个域独立建DWD事实表（交易事实、行为事实、投诉事实）
- 商家维度表是公共维度（被所有域引用）
- DWS层沉淀商家画像宽表（综合多域指标）

**和QQ频道建模的共通点：** 都是先梳理业务过程 → 划分主题域 → 每域建事实表 → 公共维度共享。方法论一致。

**四、技术知识补充**

**项目结合点：** 回答时务必结合QQ频道实际场景，体现"不是背八股，是真做过"的信号。

**五、追问预判**

1. **追问：如何判断一个需求应该放在DWD还是DWS？→ 看复用性：多个下游都用放DWS，单一场景放ADS。**

2. **追问：治理最难推的是什么？→ 历史表下线。下游依赖不清楚时谁都不敢动，需要先建血缘再评估。**

3. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。


**六、常见错误/踩坑提醒**

- ❌ 只背分层定义不说为什么 → ✅ 每层说清楚解决什么问题
- ❌ 照搬电商方案不区分业务 → ✅ 强调社交业务的特殊性（维度变化快）
- ❌ 不提治理 → ✅ 4年经验必须体现架构+治理双视角

**七、记忆版（20秒压缩）**

> 商家治理五个域：基础/交易/行为/评价/治理。每域建事实表，商家维度是公共维度。方法论和社交数仓一致。
