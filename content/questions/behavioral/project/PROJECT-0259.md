**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

体系建设四要素：

1. **规则引擎**：支持配置化定义质量规则（不用写代码）
2. **调度集成**：任务完成后自动触发质量检查
3. **告警通道**：多级告警（信息→警告→严重），按级别走不同通道
4. **治理闭环**：告警→认领→处理→复盘→改进规则

**落地顺序：** 先覆盖核心表（20%的表承载80%的价值）→ 再逐步扩展。

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：治理最难推的是什么？→ 历史表下线。下游依赖不清楚时谁都不敢动，需要先建血缘再评估。**

2. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

3. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。


**六、常见错误/踩坑提醒**

- ❌ 把治理等同于"制定规范" → ✅ 治理=规范+工具+流程+激励
- ❌ 只讲理论不讲落地 → ✅ 结合频道项目的僵尸表下线等真实案例
- ❌ 说"全部治理" → ✅ 增量严格+存量兼容，不能一刀切

**七、记忆版（15秒压缩）**

> 四要素：规则引擎(配置化) + 调度集成(自动触发) + 多级告警 + 治理闭环。先覆盖20%核心表。
