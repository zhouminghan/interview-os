**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

标准发布流程：
```text
开发 → 自测 → Code Review → 测试环境验证 → 上线审批 → 灰度发布 → 全量
```

**关键控制点：**
1. **Code Review**：SQL逻辑/性能/规范检查
2. **测试验证**：在测试环境跑通+数据抽样比对
3. **灰度发布**：先跑一天看结果正确性再切全量
4. **回滚方案**：每次发布必须有回滚Plan B

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

2. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。

3. **追问：这个方案的边界/不适用场景是什么？**
   → 任何方案都有适用范围，说清楚什么时候不应该用这个方案。


**六、常见错误/踩坑提醒**

- ❌ 只关注开发不关注运维 → ✅ 数据工程包括开发+调度+监控+运维全链路
- ❌ 不讲数据质量 → ✅ 数据工程的核心产出是"可信的数据"
- ❌ 不提自动化 → ✅ 重复工作应该自动化（监控/告警/回溯）

**七、记忆版（10秒压缩）**

> 开发→自测→Review→测试验证→审批→灰度→全量。必须有回滚方案。
