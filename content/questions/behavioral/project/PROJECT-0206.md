**一、面试官真正想考什么？**

不是让你背定义，考的是**概念理解深度和表达能力**：
- 你能否一句话抓住本质，不是背一段定义
- 你能否由浅入深地讲清楚
- 你有没有真实使用/落地的经验

**二、回答思路**

一句话定义本质 → 核心机制/原理展开 → 结合项目说落地场景 → 补充适用边界

**三、参考答案（面试标准版）**

> 控制在2分钟

```text
SQL提交 → 解析器(Parser) → 编译器(Compiler) → 优化器(Optimizer) → 执行器(Executor)
   ↓           ↓                  ↓                    ↓                    ↓
 客户端    AST语法树        逻辑执行计划         物理执行计划         MR/Spark任务
```

详细步骤：
1. **Parser**：SQL → AST抽象语法树（检查语法）
2. **Semantic Analyzer**：AST → 逻辑计划（检查表/列是否存在，类型是否匹配）
3. **Optimizer**：逻辑计划 → 优化后的逻辑计划（谓词下推/列裁剪/分区裁剪）
4. **Physical Plan**：逻辑计划 → 物理计划（决定用MapJoin还是ReduceJoin等）
5. **Execution**：物理计划 → 提交到YARN执行MR/Spark/Tez任务

**面试加分点：** 「所以当我们做SQL优化时，本质是在帮助优化器做更好的决策——比如通过Hint指定BroadcastJoin、通过表统计信息帮助CBO选择更优的Join顺序。」

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：Spark任务OOM怎么排查？→ 看Executor GC Time/Shuffle Spill/Driver Log，定位是堆内还是堆外。**

2. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

3. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。


**六、常见错误/踩坑提醒**

- ❌ 只说优化手段不说定位过程 → ✅ 先定位瓶颈（EXPLAIN/执行计划），再选方案
- ❌ 优化没有量化效果 → ✅ 必须说"从X降到Y，提升Z%"
- ❌ 把所有优化手段堆上来 → ✅ 针对具体问题选最合适的方案

**七、记忆版（20秒压缩）**

> SQL → AST → 逻辑计划 → 优化（谓词下推/列裁剪）→ 物理计划 → 提交执行。优化本质是帮优化器做更好决策。
