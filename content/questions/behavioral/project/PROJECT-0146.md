> **要点提纲**：慢任务排查 | 拆分重构 | 并行化 | 依赖链优化 | 量化结果 | AI Skill加速
> **来源**：字节-AI Agent数据开发-20260420 Q38

数据产出延迟优化做了几轮。

**第一轮是慢任务排查和重构**。有个 DWS 宽表任务跑了好几个小时，排查发现逻辑冗余——多次重复 JOIN 同一张表，中间结果没有复用。重构后用 CTE 抽取公共逻辑，拆成多个子任务并行跑，从几小时降到 1 小时以内。

**第二轮是数据倾斜治理**。热点 key 打散和参数调优后，倾斜任务的长尾 Task 耗时显著下降。

**第三轮是依赖链优化**。减少不必要的串行依赖，能并行的任务改成并行触发，整体 DAG 关键路径缩短。

**量化成果**：核心报表的产出时间从上午 10 点多提前到 8 点前。关键宽表任务从几小时降到 1 小时以内。数据出库效率通过 AI Skill 自动化创建出库任务，从 15 分钟降到 2 分钟。数据回溯从 2 小时降到 5 分钟。

除了 SQL 之外，我的技术栈还包括以下几个方面：

**1. PySQL**：在 Python 脚本中嵌入 SQL，适合动态逻辑控制的场景。比如循环回溯多个分区时，用 Python 控制日期循环，每轮动态拼接 SQL 并提交执行。

**2. AI Skill 工作流开发**：用 CodeBuddy 开发自动化 Skill，覆盖数据回溯、建模模板生成、出库任务配置等高频运维操作，目前覆盖约 80% 的日常重复性工作。

**3. MCP 协议对接**：配合正式员工接入内部平台 API（US 调度平台、OLA 数据平台等），让 AI 能直接调用内部系统的能力。

**4. 数据质量监控**：在 OLA 平台配置质量规则和告警——日环比波动、非空唯一性校验、熔断机制等。

**5. BI 报表搭建**：DataTalk 配置可视化看板，包括折线图趋势、表格明细、维度下钻，配合企微机器人做日报推送。

**6. 埋点方案评审**：从数仓视角评估客户端埋点方案的参数完整性、事件编码规范性和上报时机合理性。

> 💡 面试要点：总结就是以 SQL 为核心，辅以 Python 脚本、AI 工具和平台操作。体现的是"全链路数据工程能力"，不是只会写 SQL。
