**三、参考答案（面试标准版）**

**Checkpoint = 定期对所有算子的State做一致性快照，保存到持久化存储。**

```text
正常运行 → 触发Checkpoint → 所有算子保存State快照 → 写入HDFS/S3
   ↓
任务失败 → 从最新Checkpoint恢复State → 从对应Kafka Offset重新消费
   ↓
恢复完成 → 继续处理，不丢数据
```

**核心机制：Barrier对齐**
- JobManager定期向Source注入Barrier
- Barrier随数据流流动
- 算子收到所有输入的Barrier后做State快照
- 保证快照的一致性

**关键参数：**
```
checkpointInterval = 60s（多久做一次）
checkpointTimeout = 10min（超时则失败）
minPauseBetweenCheckpoints = 30s（两次间最小间隔）
```

**六、常见错误/踩坑提醒**

- ❌ 说"所有场景都应该上实时" → ✅ 80%场景T+1够用，实时成本是离线3-5倍
- ❌ 不提口径一致性 → ✅ 实时和离线必须同源同口径，离线为准确基准
- ❌ 只讲技术不讲业务场景 → ✅ 说清楚什么场景需要实时（监控/风控/推荐）

**七、记忆版（20秒压缩）**

> Checkpoint=定期State快照存HDFS。通过Barrier对齐保证一致性。失败后从最新Checkpoint恢复+Kafka回溯，不丢数据。
