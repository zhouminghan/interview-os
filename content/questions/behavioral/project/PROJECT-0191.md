**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

> 控制在1分钟

**粒度 = 一行数据代表什么。** 这是建表时第一个要确定的事，其他所有设计都以此为基础。

**确定方法：**
1. 找到业务最细的分析需求——如果需要看每次点击的详情，粒度就是"一次点击"
2. 粒度越细越灵活（可以向上汇总），但存储和计算成本越高
3. 权衡：DWD层尽量保持最细粒度，DWS层可以按天/周/月聚合

**示例：**
- 曝光事实表：一行 = 一次曝光（用户在某时刻看到某内容）
- 订单事实表：一行 = 一笔订单
- 用户活跃汇总表：一行 = 一个用户一天的活跃指标（这是DWS粒度）
