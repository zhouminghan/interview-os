**一、面试官真正想考什么？**

不是让你背定义，考的是**原理理解和决策判断**：
- 你是否理解底层原理，不只是"因为教程说要这样"
- 你能否说清楚选择背后的权衡
- 你有没有对比过替代方案

**二、回答思路**

先给核心原因（一句话）→ 展开2-3个具体原因 → 对比如果不这样做会怎样 → 结合项目实证

**三、参考答案（面试标准版）**

> 控制在2分钟

**核心原因：LLM缺三样东西。**

1. **缺业务知识** — LLM不知道你的表叫什么名、字段什么含义、指标怎么算
   - 它不知道"DAU"在你们公司的定义是"打开APP"还是"停留>30秒"
   - 它不知道表名是dws_channel_user_active_1d

2. **缺执行能力** — LLM只能生成文本，不能调用数据平台接口
   - 不能查血缘、不能执行SQL、不能触发任务
   - 说白了"只动嘴不动手"

3. **缺上下文** — LLM不知道当前数据状态（分区是否就绪、上游是否正常）
   - 生成的SQL可能引用了昨天还没产出的分区

**所以需要：**
- Knowledge Base → 解决"不懂业务"
- Skill → 解决"不知道怎么执行"
- MCP Tool → 解决"无法调用外部系统"
- Workflow → 解决"复杂任务的多步编排"

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

2. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。

3. **追问：这个方案的边界/不适用场景是什么？**
   → 任何方案都有适用范围，说清楚什么时候不应该用这个方案。


**六、常见错误/踩坑提醒**

- ❌ 说"我们用AI替代了开发" → ✅ AI辅助执行，人负责决策和质量
- ❌ 把自己定位为"AI算法工程师" → ✅ 准确定位Knowledge Engineer
- ❌ 只讲技术概念不讲业务痛点 → ✅ 先说业务痛点，再说AI怎么解决

**七、记忆版（20秒压缩）**

> LLM缺三样：业务知识（不知道表/指标）、执行能力（不能调接口）、实时上下文（不知道数据状态）。所以需要Knowledge+Skill+MCP补齐。
