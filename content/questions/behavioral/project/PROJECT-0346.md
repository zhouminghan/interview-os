**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

> 控制在2-3分钟

PB级数仓规划要考虑四个维度：

**1. 存储架构**
- 湖仓架构（Iceberg/Hudi on HDFS/S3）
- 冷热分离：最近30天热数据高性能存储，历史冷数据低成本存储
- 数据压缩：ORC/Parquet + Snappy/ZSTD
- 生命周期管理：超过TTL自动归档/删除

**2. 计算架构**
- Spark为主力（大规模批处理能力强）
- 资源隔离：核心任务和探索任务分Queue
- 弹性扩缩：峰谷时段动态调整资源
- 增量计算优先：全量重跑只在必要时

**3. 数据分层设计**
- ODS → DWD → DWS → ADS 标准分层
- 规范先行：命名/分区/字段标准第一天定好
- 公共层先行：先建DWS再建ADS，避免重复计算

**4. 治理体系**
- 元数据管理 + 血缘 + 质量监控
- 成本管控：任务级成本核算，推动无效任务下线
- 容量规划：定期评估存储/计算增长趋势

**一句话架构理念：** PB级不是"更大的数仓"，而是需要体系化的成本控制和治理能力。

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：Spark任务OOM怎么排查？→ 看Executor GC Time/Shuffle Spill/Driver Log，定位是堆内还是堆外。**

2. **追问：如何判断一个需求应该放在DWD还是DWS？→ 看复用性：多个下游都用放DWS，单一场景放ADS。**

3. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。


**六、常见错误/踩坑提醒**

- ❌ 只讲技术不讲软技能 → ✅ S6级别需要架构能力+推动能力+方法论
- ❌ 不展现成长路径 → ✅ 从执行者→设计者→推动者的转变
- ❌ 对AI的态度极端(替代/无用) → ✅ 会用AI的人替代不会用的人

**七、记忆版（20秒压缩）**

> 四维度：存储(湖仓+冷热分离+压缩+生命周期)、计算(Spark+资源隔离+弹性+增量)、分层(规范先行+公共层优先)、治理(血缘+成本+容量)。PB级核心是成本控制和治理。
