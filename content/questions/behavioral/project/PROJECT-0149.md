> **要点提纲**：四步交互链路 | 意图识别 → 上下文加载 → MCP 调用 → 三段式审核 | LLM/MCP/DE 三层解耦
> **来源面经**：字节-AI Agent数据开发一面-20260412 Q5

我们这边语义解析没有自己训模型，直接走的是 **LLM + Prompt + Skill 路由**这套范式，整个交互链路分四步：

**第一步是意图识别**——用户用自然语言输入需求（"帮我建一个频道日活宽表"），CodeBuddy（AI Coding Agent）的内置路由根据触发关键词匹配到对应 Skill。Skill 本质是一份用 Markdown 写的 SOP + 工作流配置，告诉 AI 该走什么流程、加载哪些上下文、调用哪些工具。

**第二步是上下文加载**——Skill 启动后强制加载业务知识库（表元数据、口径定义、命名规范）等必要上下文，作为 LLM 的输入。

**第三步是 MCP 工具调用**——LLM 决定要做什么之后，通过 MCP 协议调用平台能力。MCP 是 AI 和外部系统之间的标准化协议，平台侧把"查表元数据""查分区""建调度任务""发起出库"等能力封装成 MCP 工具，AI 像调用函数一样调用。比如建模 Skill 会先调 `getTableDDL` 拿上游表结构，再调 `previewTableName` 校验目标表名规范，最后生成 SQL。

**第四步是三段式审核**——AI 生成的方案（SQL / 任务配置）必须先返回给 DE 看，DE 审核确认后再触发 MCP 真正落地（建任务、出库等），关键操作绝不全自动。

整体交互的核心思想是：**LLM 负责理解和编排，MCP 负责真实执行，DE 负责审核把关**，三者解耦。

> 💡 面试要点：这道题考察对 AI Agent 系统架构的理解。回答里要体现三个层次——具体链路（四步走）、核心协议（MCP 是什么、为什么需要）、设计哲学（LLM/MCP/DE 三层解耦）。能讲到第三层就是高分回答。
