**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

数据开发平台核心能力分四层：

```text
用户层：SQL IDE + 可视化拖拽 + 任务管理
调度层：DAG编排 + 依赖管理 + 定时触发
计算层：Spark/Hive/Flink引擎对接
存储层：HDFS/Iceberg/数据字典/元数据
```

**核心设计原则：**
1. **一站式**：开发/调试/上线/监控在同一平台完成
2. **规范内嵌**：命名规范/质量规则集成到平台，不靠人记
3. **自助化**：降低使用门槛（非技术人员也能用）
4. **可观测**：任务状态/性能/依赖一目了然

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：Spark任务OOM怎么排查？→ 看Executor GC Time/Shuffle Spill/Driver Log，定位是堆内还是堆外。**

2. **追问：Hive和Spark SQL有什么区别？→ Hive底层是MR（慢），Spark SQL底层是DAG（快），但Hive MetaStore两者共用。**

3. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。


**六、常见错误/踩坑提醒**

- ❌ 只关注开发不关注运维 → ✅ 数据工程包括开发+调度+监控+运维全链路
- ❌ 不讲数据质量 → ✅ 数据工程的核心产出是"可信的数据"
- ❌ 不提自动化 → ✅ 重复工作应该自动化（监控/告警/回溯）

**七、记忆版（15秒压缩）**

> 四层：用户(IDE/管理)+调度(DAG/依赖)+计算(引擎)+存储(HDFS/元数据)。原则：一站式+规范内嵌+自助化+可观测。
