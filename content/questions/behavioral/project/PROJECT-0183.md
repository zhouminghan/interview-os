**一、面试官真正想考什么？**

不是问你"什么是数据资产"（概念），而是考：
- 你是否有落地经验（不只是理论）
- 你能否把抽象概念转化为具体工作
- 你是否有平台化/体系化思维

**二、回答思路**

定义问题 → 建设体系（四个维度）→ 落地经验

**三、参考答案（面试标准版）**

> 控制在2分钟

我理解，数据资产建设的核心目标是**让数据被发现、被理解、被复用**。

我们的做法分四个维度：

**第一，元数据标准化。**
- 表命名规范（层级_主题域_业务过程_时间粒度）
- 字段标注（中文含义、数据类型、取值范围、是否可空）
- 指标口径统一（一个指标只有一个官方定义）

**第二，数据地图建设。**
- 可视化展示表与表的依赖关系
- 支持按主题域、业务线、数据层级浏览
- 搜索能力：通过指标名/表名/字段名快速定位资产

**第三，血缘关系维护。**
- SQL解析自动建立表级/字段级血缘
- 用于影响分析（改一张表，哪些下游受影响）
- 用于资产价值评估（被引用多的是核心资产）

**第四，资产健康度管理。**
- 定期扫描无访问、无依赖的表（僵尸资产）
- 通过数据地图/访问记录/任务依赖判断使用情况
- 推动下线或冻结，释放存储和计算资源

**落地经验：** 在QQ频道项目中，频道低版本手Q下线、历史页面废弃后，对应的表变成无人使用资产。我通过以上体系识别出这些僵尸表，并推动下线。

**四、技术知识补充**

资产健康度评估模型：
```text
资产得分 = 使用频率（40%）+ 下游引用数（30%）+ 数据质量（20%）+ 文档完善度（10%）

健康：得分 > 80，核心资产
亚健康：得分 40-80，需关注
不健康：得分 < 40，候选下线
```

**五、追问预判**

1. **追问：如何推动资产下线？业务方不配合怎么办？**
   → 先建数据 → 用数据说话（"这张表90天无人查询"） → 设冷冻期（停止更新但保留数据）→ 冷冻期无人反馈才正式下线。

2. **追问：指标口径不一致怎么解决？**
   → 建设指标字典：每个指标有唯一负责人、唯一计算逻辑、唯一数据来源。冲突时由数仓团队裁定统一口径。

3. **追问：复用率怎么衡量？**
   → 被3个以上业务线使用的公共表占比。{需要补充：具体提升数据}

**六、常见错误/踩坑提醒**

- ❌ 把"数据资产"等同于"建几张表" → ✅ 资产建设是体系工程（标准化+可发现+可复用+可治理）
- ❌ 只说理论不说落地 → ✅ 结合QQ频道的僵尸资产下线案例

**七、记忆版（30秒压缩）**

> 数据资产建设 = 让数据被发现、被理解、被复用。四维度：元数据标准化（命名/字段/口径）、数据地图（可视化浏览）、血缘维护（影响分析）、健康度管理（僵尸表下线）。
