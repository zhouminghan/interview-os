**一、面试官真正想考什么？**

不是让你背定义，考的是**实操经验和问题解决能力**：
- 你是否有真实的动手经验
- 你能否讲清楚具体的做法和效果
- 你对这个问题的理解深度

**二、回答思路**

先给结论 → 展开核心要点（不超过3个）→ 结合项目经验 → 适用边界

**三、参考答案（面试标准版）**

**数据血缘 = 数据从源头到最终消费的完整流转路径。** 回答"这个数据从哪来、经过什么加工、最终到了哪里"。

两个粒度：
- **表级血缘**：表A → ETL → 表B → ETL → 表C
- **字段级血缘**：表A.col1 → 计算逻辑 → 表B.col2

**核心价值：**
- 影响分析：改表A会影响哪些下游？
- 根因追溯：表C数据异常，问题源头在哪？
- 资产评估：哪些表是核心资产（被大量引用）？

**四、技术知识补充**

本题涉及的核心技术点（面试中可能被深挖）：
- **表级血缘**：理解其原理和适用场景，不要只记结论
- **字段级血缘**：理解其原理和适用场景，不要只记结论

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

2. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。

3. **追问：这个方案的边界/不适用场景是什么？**
   → 任何方案都有适用范围，说清楚什么时候不应该用这个方案。


**六、常见错误/踩坑提醒**

- ❌ 把治理等同于"制定规范" → ✅ 治理=规范+工具+流程+激励
- ❌ 只讲理论不讲落地 → ✅ 结合频道项目的僵尸表下线等真实案例
- ❌ 说"全部治理" → ✅ 增量严格+存量兼容，不能一刀切

**七、记忆版（15秒压缩）**

> 数据血缘=数据流转路径（从哪来/怎么加工/到哪去）。价值：影响分析+根因追溯+资产评估。
