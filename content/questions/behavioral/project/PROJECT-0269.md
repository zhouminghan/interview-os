**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

四个层次：
1. **自助取数**：提供可视化查询工具，业务方不需要写SQL
2. **公共指标层**：常用指标在DWS预计算，一键查看不需要等待计算
3. **数据产品化**：固定需求做成看板/报表，不需要每次临时取数
4. **AI取数**：自然语言描述需求 → AI生成SQL → 返回结果

**结合AI项目：** 我们的取数Agent让运营可以用自然语言查数据，简单需求从"提工单等3天"变成"对话秒级返回"。

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：AI生成的SQL出错了谁负责？→ 人负责。AI辅助生成，人Review确认，最终质量由人把关。**

2. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

3. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。


**六、常见错误/踩坑提醒**

- ❌ 把治理等同于"制定规范" → ✅ 治理=规范+工具+流程+激励
- ❌ 只讲理论不讲落地 → ✅ 结合频道项目的僵尸表下线等真实案例
- ❌ 说"全部治理" → ✅ 增量严格+存量兼容，不能一刀切

**七、记忆版（15秒压缩）**

> 四层次：自助工具(可视化) → 公共指标(DWS预计算) → 数据产品(看板) → AI取数(自然语言)。
