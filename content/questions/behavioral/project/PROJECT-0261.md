**一、面试官真正想考什么？**

不是让你背定义，考的是**实操经验和问题解决能力**：
- 你是否有真实的动手经验
- 你能否讲清楚具体的做法和效果
- 你对这个问题的理解深度

**二、回答思路**

先给结论 → 展开核心要点（不超过3个）→ 结合项目经验 → 适用边界

**三、参考答案（面试标准版）**

详细展开（补充Q85）：

| 分类 | 内容 |
|------|------|
| 技术 | 数据库/表名/字段名/类型/分区/存储格式/压缩方式/数据量/文件数 |
| 业务 | 中文表名/字段中文注释/指标计算逻辑/数据口径/负责人/所属主题域 |
| 运营 | 每日查询次数/下游依赖数/最后更新时间/数据延迟/血缘上下游 |
| 安全 | 数据分级（公开/内部/机密）/脱敏规则/访问权限 |

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

2. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。

3. **追问：这个方案的边界/不适用场景是什么？**
   → 任何方案都有适用范围，说清楚什么时候不应该用这个方案。


**六、常见错误/踩坑提醒**

- ❌ 把治理等同于"制定规范" → ✅ 治理=规范+工具+流程+激励
- ❌ 只讲理论不讲落地 → ✅ 结合频道项目的僵尸表下线等真实案例
- ❌ 说"全部治理" → ✅ 增量严格+存量兼容，不能一刀切

**七、记忆版（10秒压缩）**

> 技术(结构)+业务(含义)+运营(使用)+安全(权限)四类信息。
