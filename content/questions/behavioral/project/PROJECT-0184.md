**一、面试官真正想考什么？**

不是问你用了什么AI技术（大模型/Agent这些词谁都会说），而是考：
- 你对AI落地的理解是否务实
- 你在AI项目中的角色定位
- AI到底解决了什么真实问题

**二、回答思路**

项目定位（15秒）→ 技术架构（30秒）→ 三类场景（60秒）→ 我的核心角色（20秒）

**三、参考答案（面试标准版）**

> 控制在2-3分钟

**项目定位：** 这不是自研Agent平台，而是基于公司已有的Agent平台，做业务应用层的AI落地。我的角色是Knowledge Engineer——连接业务知识和AI能力的桥梁。

**技术架构：**
```text
用户需求 → Agent → Workflow编排 → Knowledge Base → Skill → MCP Tool → 数据平台接口
```

**三类落地场景：**

**场景一：数据回溯自动化。**
- 传统方式：手动查血缘 → 检查上游分区 → 写SQL → 执行 → 核对结果（1-2小时）
- AI方式：Skill + MCP自动获取血缘 → 检查上游分区状态 → 生成回溯SQL → 自动执行并返回结果
- 效果：从1-2小时缩短到分钟级

**场景二：业务知识库 + 取数Agent。**
- 沉淀到知识库：表结构/字段含义/指标口径/建模规范/SQL模板
- 运营和产品通过自然语言取数，AI基于知识库生成SQL
- 解决"AI不懂业务"的核心问题

**场景三：需求开发辅助。**
- AI参与需求分析、方案设计、SQL生成
- 人负责Review和质量把控
- 模式：AI辅助，人把关

**我的核心工作：** 搭建业务知识库（表/字段/指标/规范），设计Skill（让AI知道如何执行具体任务），配置Workflow编排（多步骤任务串联）。

**四、技术知识补充**

知识库 vs Skill vs MCP 的区别：
```text
Knowledge Base：AI"知道什么"（业务知识、表结构、指标定义）
Skill：AI"怎么做"（执行步骤、工具调用方式、参数规范）
MCP：AI"用什么工具"（对接外部系统的能力，如查询血缘API、执行SQL API）
```

Bitmap模型优化案例：
- 知识库中沉淀了Bitmap模型和DF/DI建模规范
- AI理解规则后计算留存不会直接扫描30天日志
- 而是优先使用Bitmap模型，只扫描一天数据

**五、追问预判**

1. **追问：知识库里具体存什么？**
   → 五类内容：① 表结构（DDL + 字段含义）② 指标定义（计算逻辑 + 口径说明）③ 建模规范（命名规则 + 设计原则）④ SQL模板（常见查询模式）⑤ 业务上下文（主题域关系 + 数据流转路径）

2. **追问：AI生成的SQL怎么保证正确？**
   → 三层校验：① 语法校验（Explain通过）② 语义校验（对比知识库中的指标定义）③ 人工Review（核心任务必须人确认）

3. **追问：实际带来多少提效？**
   → 见Q10

**六、常见错误/踩坑提醒**

- ❌ 「我们用大模型做了一个Agent」（太虚） → ✅ 具体说清楚三类场景和解决的真实问题
- ❌ 把自己说成"大模型开发者" → ✅ 准确定位为Knowledge Engineer（知识工程师）
- ❌ 「AI自动完成所有开发」 → ✅ 强调"AI辅助，人把关"的模式

**七、记忆版（30秒压缩）**

> 基于公司Agent平台做业务AI落地，我是Knowledge Engineer。三个场景：数据回溯自动化（Skill+MCP）、取数Agent（知识库解决AI不懂业务）、开发辅助（AI生成+人Review）。核心：知识库=AI知道什么，Skill=AI怎么做，MCP=AI用什么工具。
