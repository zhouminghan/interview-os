**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

四步推动法：

1. **对齐目标** — 让所有干系方理解"为什么要做"和"做完对大家有什么好处"
2. **明确边界** — 谁负责什么、什么时间完成、交付标准是什么
3. **建立机制** — 定期同步会+进度看板+问题升级通道
4. **数据驱动** — 用数据展示进展和效果，减少主观争议

**常见困难和应对：**
- 优先级冲突：找到共同上级对齐优先级
- 配合不积极：用数据说明收益（"做完后你的团队也能省X人天"）
- 标准不统一：先小范围达成共识，再逐步推广

**结合项目：** 数据治理需要跨团队（数据开发/产品/运营），推动方式是"先用数据证明痛点（僵尸表X张，冗余计算Y%），再提出治理方案和分工"。

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：治理最难推的是什么？→ 历史表下线。下游依赖不清楚时谁都不敢动，需要先建血缘再评估。**

2. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

3. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。


**六、常见错误/踩坑提醒**

- ❌ 只讲技术不讲软技能 → ✅ S6级别需要架构能力+推动能力+方法论
- ❌ 不展现成长路径 → ✅ 从执行者→设计者→推动者的转变
- ❌ 对AI的态度极端(替代/无用) → ✅ 会用AI的人替代不会用的人
