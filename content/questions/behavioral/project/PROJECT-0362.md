# 面试官原问题

> 你现在感觉也做了一些治理的事情，这块治理主要是哪些方面的工作？

后续追问：

> 元数据治理这块，我理解是一些规范治理，对吧？这种治理工作你们怎么推进？

> 规范编写、表规范这些动作，是你主导的吗？

---

# 一、回答思路

这道题非常关键。

因为很多数仓开发回答：

> 我做过数据治理，包括数据质量、血缘、元数据。

然后结束。

面试官听完不知道你到底做了什么。

真正好的回答需要体现：

**数据治理不是一个工具，而是一套持续管理机制。**

回答结构：

```
治理背景
 ↓
治理分类
 ↓
具体措施
 ↓
推进方式
 ↓
业务价值
```

---

# 标准回答（求职者视角）

> 数据治理这块我们主要结合频道业务的发展阶段去做。
>
> 因为频道业务持续迭代，历史上积累了很多表、指标和任务，如果缺少治理，后续会出现：
>
> * 表越来越多，不知道哪个能用
> * 指标口径不一致
> * 数据质量问题发现不及时
> * 资源消耗越来越高
>
> 所以我们主要从四个方向推进：
>
> 1. 元数据治理
> 2. 数据质量治理
> 3. 数据资产治理
> 4. 资源治理

---

# 二、元数据治理

## 面试回答

> 第一块是元数据治理，主要解决数据资产不可理解、不可复用的问题。

主要包含：

### 1. 表规范治理

例如：

统一：

```
分层
业务域
主题域
表用途
```

比如：

```
dwd_xxx_xxx
dws_xxx_xxx
ads_xxx_xxx
```

让开发人员看到表名，就能基本判断用途。

---

### 2. 字段规范

例如：

用户ID：

不能：

A表：

```
uid
```

B表：

```
user_id
```

C表：

```
userid
```

统一：

```
user_id
```

---

### 3. 指标口径治理

这是重点。

比如：

登录UV。

不同开发可能写：

```sql
count(user_id)
```

或者：

```sql
count(distinct user_id)
```

导致指标不一致。

所以需要：

沉淀：

* 指标名称
* 指标定义
* 计算逻辑
* 数据来源

# 三、数据质量治理

回答：

> 第二块是数据质量治理，主要保证数据可靠。

我们主要关注几个方面：

---

## 1. 完整性

例如：

每天分区是否正常生成。

检查：

```
dt=2026-07-16
```

是否存在。

---

## 2. 准确性

例如：

ODS到DWD加工。

检查：

源数据量：

```
100万
```

目标：

```
99.8万
```

如果差异异常，需要定位。

---

## 3. 唯一性

例如：

业务主键：

```
channel_id
user_id
```

不能出现大量重复。

---

## 4. 波动监控

这个是你的项目亮点。

回答：

> 对于一些核心业务指标，我们会增加合理性检测。

例如：

频道帖子量。

统计历史30天：

* 最大值
* 最小值
* 平均值

设置波动阈值。

如果：

```
今日相比昨日下降80%
```

触发告警。

---

# 四、数据资产治理

回答：

> 第三块是数据资产治理，主要解决历史资产不断累积的问题。

例如：

频道业务长期发展后：

会出现：

* 老表
* 废弃任务
* 无人使用看板

处理方式：

---

## 1. 表生命周期管理

例如：

长期没有访问：

进入：

```
观察期

↓

冻结

↓

下线
```

---

## 2. 血缘分析

通过血缘：

判断：

```
哪些表被依赖
```

避免误删。

---

## 3. 提升复用率

例如：

发现多个业务重复加工：

```
DWD日志表
```

产生：

```
用户行为指标
```

可以沉淀公共DWS。

# 六、治理如何推进？

## 优化回答：

> 数据治理一般不会单独停掉业务开发做专项治理，因为业务持续迭代。

所以我们的方式：

### 存量：

兼容治理。

例如：

历史表：

```
login_table
```

已经被大量任务依赖。

不直接修改。

而是：

补充：

* 元数据
* 血缘
* 主题域归属

---

### 增量：

严格治理。

新建表：

必须符合：

* 命名规范
* 分层规范
* 指标规范
* 数据质量要求

# 七、技术正确性检查

这里几个地方需要注意。

---

## 1. “元数据治理保证数据来源一致”

不完全准确。

元数据治理：

主要解决：

* 描述
* 发现
* 血缘
* 管理

指标一致性属于：

数据标准治理。

面试可以说：

> 元数据和数据标准共同保证指标可追溯。

更严谨。

---

## 2. 数据质量四个维度

常见：

* 完整性 Completeness
* 准确性 Accuracy
* 一致性 Consistency
* 唯一性 Uniqueness
* 时效性 Timeliness

你回答里面可以增加：

时效性。

---

## 3. “字段安全定级”

这是数据安全治理。

属于数据治理范畴。

可以补充：

例如：

用户ID、手机号等：

按照敏感等级：

```
公开
内部
敏感
高敏
```

控制：

权限申请。

# 面试最终版本控制在 2分钟左右：

> 我们频道数据治理主要从四个方面展开……
>
> 第一是元数据和标准治理，包括表规范、字段规范、指标口径统一。
>
> 第二是数据质量治理，包括完整性、准确性、时效性和业务合理性监控。
>
> 第三是资产治理，通过血缘和生命周期管理清理无效资产，提高复用率。
>
> 第四是资源治理，通过SQL优化、模型优化、Spark调优降低计算成本。
>
> 推进上我们采用增量严格治理、存量兼容治理的方式，因为历史表依赖比较复杂，不能为了规范强行修改影响线上业务。

这个版本面试官会认为你已经从“开发人员”提升到了“数仓工程能力”。
