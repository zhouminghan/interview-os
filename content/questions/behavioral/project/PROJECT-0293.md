**一、面试官真正想考什么？**

不是让你背定义，考的是**原理理解和决策判断**：
- 你是否理解底层原理，不只是"因为教程说要这样"
- 你能否说清楚选择背后的权衡
- 你有没有对比过替代方案

**二、回答思路**

先给核心原因（一句话）→ 展开2-3个具体原因 → 对比如果不这样做会怎样 → 结合项目实证

**三、参考答案（面试标准版）**

**因为复杂任务不是一步能完成的。** 需要多步骤有序执行，步骤间有依赖关系和条件判断。

例如"数据回溯"不是一步：
```text
获取血缘 → 检查上游 → [如果上游没准备好：等待/告警] → 生成SQL → 执行 → 验证
```

Workflow编排的价值：
1. **流程可视化**：复杂逻辑变成可读的流程图
2. **错误处理**：每步失败有明确的处理策略
3. **可复用**：同一Workflow可以被不同场景复用
4. **可审计**：每步执行记录可追溯

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

2. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。

3. **追问：这个方案的边界/不适用场景是什么？**
   → 任何方案都有适用范围，说清楚什么时候不应该用这个方案。


**六、常见错误/踩坑提醒**

- ❌ 说"我们用AI替代了开发" → ✅ AI辅助执行，人负责决策和质量
- ❌ 把自己定位为"AI算法工程师" → ✅ 准确定位Knowledge Engineer
- ❌ 只讲技术概念不讲业务痛点 → ✅ 先说业务痛点，再说AI怎么解决

**七、记忆版（10秒压缩）**

> 复杂任务需要多步骤有序执行+条件判断+错误处理。Workflow让复杂逻辑可视化、可复用、可审计。
