**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

技术选型五步法：

1. **明确需求** — 要解决什么问题？性能/成本/维护/扩展哪个优先？
2. **候选方案** — 列出2-3个候选技术
3. **评估维度** — 功能满足度/性能/成本/社区活跃度/团队熟悉度/运维复杂度
4. **验证测试** — POC验证核心场景性能
5. **决策记录** — 记录选择原因（为什么选A不选B），方便后续回溯

**选型原则：**
- 成熟优于新潮（生产环境要稳定）
- 生态优于单点（和已有技术栈兼容）
- 团队能力匹配（选团队能驾驭的）

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

2. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。

3. **追问：这个方案的边界/不适用场景是什么？**
   → 任何方案都有适用范围，说清楚什么时候不应该用这个方案。


**六、常见错误/踩坑提醒**

- ❌ 只讲技术不讲软技能 → ✅ S6级别需要架构能力+推动能力+方法论
- ❌ 不展现成长路径 → ✅ 从执行者→设计者→推动者的转变
- ❌ 对AI的态度极端(替代/无用) → ✅ 会用AI的人替代不会用的人

**七、记忆版（15秒压缩）**

> 五步：明确需求→列候选→多维评估→POC验证→决策记录。原则：成熟>新潮，生态>单点，团队能驾驭。
