**一、面试官真正想考什么？**

不是让你背定义，考的是**实操经验和问题解决能力**：
- 你是否有真实的动手经验
- 你能否讲清楚具体的做法和效果
- 你对这个问题的理解深度

**二、回答思路**

先给结论 → 展开核心要点（不超过3个）→ 结合项目经验 → 适用边界

**三、参考答案（面试标准版）**

五类核心内容：

| 类型 | 示例 |
|------|------|
| 表结构 | DDL + 每个字段的中文含义和取值说明 |
| 指标定义 | "DAU = 当天打开频道且停留>10秒的去重用户数" |
| SQL模板 | 计算7日留存的标准SQL写法 |
| 建模规范 | 命名规则、分区策略、字段类型标准 |
| 业务上下文 | 主题域划分、数据流转路径、表间关系 |

**特殊内容：** Bitmap模型规范 — 让AI知道计算留存优先用Bitmap而不是扫30天日志。

**四、技术知识补充**

**项目结合点：** 回答时务必结合QQ频道实际场景，体现"不是背八股，是真做过"的信号。

**五、追问预判**

1. **追问：AI生成的SQL出错了谁负责？→ 人负责。AI辅助生成，人Review确认，最终质量由人把关。**

2. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

3. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。


**六、常见错误/踩坑提醒**

- ❌ 说"我们用AI替代了开发" → ✅ AI辅助执行，人负责决策和质量
- ❌ 把自己定位为"AI算法工程师" → ✅ 准确定位Knowledge Engineer
- ❌ 只讲技术概念不讲业务痛点 → ✅ 先说业务痛点，再说AI怎么解决

**七、记忆版（10秒压缩）**
