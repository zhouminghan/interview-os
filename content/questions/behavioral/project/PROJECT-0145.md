> **要点提纲**：DWS宽表倾斜 | 逐层排查 | 热点key打散 | 任务拆分 | 监控补位 | 复盘方法论
> **来源**：字节-AI Agent数据开发-20260420 Q35

最复杂的一次是 DWS 宽表任务持续跑好几个小时，有时候直接超时失败，严重影响下游报表产出。

**定位过程**：先看执行计划，发现某个 Stage 的几个 Task 耗时特别长，其他 Task 早就跑完了——典型的数据倾斜。进一步排查是哪个 JOIN 操作导致的，发现是宽表关联频道维度时，头部热门频道的数据量占了全量的 30%+，导致对应 Reducer 压力极大。

**解决方案用了组合手段**：第一是热点 key 打散——把 Top 频道 ID 加随机后缀分散到多个 Reduce 任务。第二是大任务拆分——按业务域拆成多个子任务并行跑，降低单任务数据量和失败重试成本。第三是参数调优——开启 AQE，调大 shuffle partition。

**复盘收获**：一是建立了大表 JOIN 的数据分布分析机制，上线前先看 key 分布。二是加了任务执行监控，跑太久自动告警，不等超时才发现。三是和团队分享了数据倾斜的排查方法论，形成文档沉淀。
