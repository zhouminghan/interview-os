**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

> 控制在2分钟

```sql
EXPLAIN EXTENDED SELECT ...
```

关注四个关键信息：
1. **Stage依赖关系** — 有多少Stage，是否有不必要的Shuffle
2. **Map Operator** — 扫描了什么表、有没有谓词下推、有没有分区裁剪
3. **Reduce Operator** — 做了什么操作（Join/GroupBy/Sort）
4. **数据量估算** — rows字段判断数据规模

**实际使用：**
- 看到"Broadcast Hash Join" → 好，小表广播避免Shuffle
- 看到"Sort Merge Join" → 检查是否可以改成Broadcast
- 看到全表扫描（没有分区过滤）→ 加WHERE条件命中分区

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：AI生成的SQL出错了谁负责？→ 人负责。AI辅助生成，人Review确认，最终质量由人把关。**

2. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

3. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。


**六、常见错误/踩坑提醒**

- ❌ 只说优化手段不说定位过程 → ✅ 先定位瓶颈（EXPLAIN/执行计划），再选方案
- ❌ 优化没有量化效果 → ✅ 必须说"从X降到Y，提升Z%"
- ❌ 把所有优化手段堆上来 → ✅ 针对具体问题选最合适的方案

**七、记忆版（15秒压缩）**

> Explain看四件事：Stage数量/Map端有无谓词下推/Reduce端Join类型/数据量估算。重点关注是否有不必要的Shuffle和全表扫描。
