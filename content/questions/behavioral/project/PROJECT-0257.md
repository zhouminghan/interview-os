**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

四层保障：
1. **源头管控**：数据接入层做格式校验和去重
2. **逻辑校验**：ETL中加断言（如金额不为负、日期格式合法）
3. **交叉验证**：核心指标多源对比（如自己算的DAU和产品端埋点的DAU做校验）
4. **人工抽检**：定期抽样核查数据正确性

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

2. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。

3. **追问：这个方案的边界/不适用场景是什么？**
   → 任何方案都有适用范围，说清楚什么时候不应该用这个方案。


**六、常见错误/踩坑提醒**

- ❌ 把治理等同于"制定规范" → ✅ 治理=规范+工具+流程+激励
- ❌ 只讲理论不讲落地 → ✅ 结合频道项目的僵尸表下线等真实案例
- ❌ 说"全部治理" → ✅ 增量严格+存量兼容，不能一刀切

**七、记忆版（15秒压缩）**

> 四层：源头校验(格式/去重) → 逻辑断言(合法性) → 交叉验证(多源对比) → 人工抽检(兜底)。
