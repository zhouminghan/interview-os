**一、面试官真正想考什么？**

不是让你背定义，考的是**方法论和实操能力**：
- 你有没有成体系的方法论，不是零散的点子
- 你能否结合真实项目说明具体做法
- 你对方案的边界和取舍是否清晰

**二、回答思路**

先给方法论框架 → 分步展开核心要点 → 结合项目举例 → 补充边界和注意事项

**三、参考答案（面试标准版）**

**划分规则：遇到Shuffle（宽依赖）就切一个新Stage。**

- 窄依赖（map/filter/union）→ 同一Stage内Pipeline
- 宽依赖（groupBy/join/repartition）→ 切分新Stage

```text
read → filter → map  [Stage 1: 窄依赖Pipeline]
         ↓ shuffle
groupBy → map → write [Stage 2: 新Stage]
```

**为什么这样切？** 窄依赖可以在同一个Task内Pipeline完成（上游一条数据处理完直接传下游）。宽依赖需要等上游所有数据处理完才能开始（因为要重新分布）。

**四、技术知识补充**

**项目结合点：** 回答时主动关联QQ频道的实际场景，增强可信度。

**五、追问预判**

1. **追问：这个方案在你的项目中是怎么落地的？**
   → 结合QQ频道百亿级日志的实际场景，说明具体做法和效果。

2. **追问：如果重新设计，你会改什么？**
   → 体现反思能力：讲一个当初的取舍，现在回头看可以优化的点。

3. **追问：这个方案的边界/不适用场景是什么？**
   → 任何方案都有适用范围，说清楚什么时候不应该用这个方案。


**六、常见错误/踩坑提醒**

- ❌ 直接说调参数 → ✅ 先通过Spark UI定位问题类型，再针对性优化
- ❌ 不区分倾斜类型 → ✅ Join倾斜/聚合倾斜/分区不均方案不同
- ❌ 忽略全链路影响 → ✅ 优化一个环节可能影响下游（如增加分区→小文件）

**七、记忆版（15秒压缩）**
