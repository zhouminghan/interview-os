# 面经记录（原始）

> 问了三四次退款场景，整体覆盖：退款指标、场景优化与原理、实时回刷、大模型取数权限/准确率、知识库与元数据维护。

1. 项目：下单取消 / 申请退款影响哪些指标；退款怎么处理
2. 任务运行涨到 2 小时，数据量只增 15%，少数 task 慢，平均 CPU 40%，如何排查
3. 调优增加并行度、executor 数量翻倍，总是有效吗
4. 如何区分数据倾斜，还是单纯某个节点硬件慢或 IO 问题
5. 确定热点 key，加盐打散是不是永远有效？生效 / 不生效原因
6. join 和 group by 倾斜，处理方式的差异
7. 结合执行计划：salt 加盐、broadcast 广播 join、hash join 区别；广播时内存是谁的内存
8. 跨天退款：今天申请退款第二天完成 / 今日下单次日退款，计算日交易额，如何避免重复扣减
9. Doris 白天每隔几秒写一批查询延迟高，晚上停止写入查询恢复，说下大概原因；改成每分钟一批，查询立刻变快吗，说明什么
10. ADS 表支持聚合查询，订单/退款修订，表 key 如何设计；解释分区分桶区别
11. Kafka-Flink 中间状态设计：订单流迟到事件、重复发送，维护订单最新状态；退款下单后又退款、数据迟到，如何准确判断订单最新状态，状态怎么维护
12. CPU 整体 45%，某一 subtask 长期满载、产生上游反压，排查和解决；为什么反压会导致 checkpoint barrier 阻塞
13. 实时作业修改口径，回刷近七天历史怎么做；实时持续消费新数据如何避免互相覆盖；回刷失败/口径再调整如何切回旧版本
14. 知识库准确率指标怎么算，测试集是什么；大模型产出两个 SQL 写法不同、结果相同如何判定
15. 上游字段改名、schema 变更、数据库维护、旧版本维护降级
16. 大模型取数权限控制完整链路：提交查询到返回结果整个流程权限校验
