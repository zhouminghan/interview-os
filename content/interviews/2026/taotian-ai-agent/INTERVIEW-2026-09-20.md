# 面经记录（原始）

面试时长 50min

1. 自我介绍
2. 先说说你做过的智能体完整执行链路，从用户发起提问到最终返回结果，中间都经过哪些核心环节，完整描述整条流程
3. 挑一个你最核心的项目来讲，这个项目实际解决了业务上什么痛点？项目周期里哪些模块是你独立开发、落地上线的？
4. 你怎么理解 RAG 底层原理，从头到尾梳理一遍 RAG 从输入到输出的完整落地流程
5. 上线 RAG 系统的时候你做过哪些调优？项目里文档切片一般用什么方式？不同业务场景下你怎么确定 Chunk 大小和重叠度这两个参数？
6. 当对话上下文快要塞满模型窗口上限，你会怎么处理？像直接截断对话历史、历史摘要压缩、对话持久化存外部数据库，分别适合什么业务场景，讲讲你的选型理由
7. 如果待处理的文本体量巨大，超出模型上下文窗口限制，行业里有哪些解决办法，结合你的项目实践谈一谈
8. Function Calling 经常遇到调用失败、参数传错这类问题，碰到这类故障你的排查思路是什么，会用什么办法修复？
9. 聊聊 Multi-Agent 多智能体架构的实现思路。什么场景适合拆成多个 Agent 而不是只用单个 Agent？多个 Agent 之间怎么分工、传递消息、协同完成任务？
10. Agent 的记忆体系一般分为哪几类？短期记忆、长期记忆分别有哪些实现方案，落地时该怎么设计？
11. 你怎么理解大模型的「自我进化」能力？这套机制是怎么跑起来的？结合你的项目说说你是怎么落地这个能力的
12. 项目中大模型微调是谁主导的？你有没有参与微调相关工作，具体负责哪些任务？
13. 微调所用的训练数据集来源是什么？拿到原始数据之后，数据清洗、筛选、标注整套流程你是怎么操作的？
14. 微调完成后模型能力提升体现在哪些地方？你会用哪些量化指标评估微调带来的收益？
15. 日常工作中你会怎么评估大模型和 AI 应用的效果？重点看哪些核心指标？对比普通大模型问答评测，Agent 智能体评测最大的区别在哪？
16. 分享一个你落地后效果没达到预期的项目，分析背后根本原因。如果让你重新迭代，会从哪些方向优化？
17. 在电商业务场景下，Agent 工具调用会频繁查询商品、订单数据，怎么保证工具返回的业务数据准确，同时控制接口调用成本？
18. RAG 检索的时候经常会出现检索无关文档、产生幻觉，结合电商场景你会采用哪些策略来降低幻觉问题？

> 备注：来源小红书（原帖未注明社招 / 校招，从面试时长 50min、18 题全链路深度、涉及微调主导权与收益量化评估来看，判断为社会招聘）。
>
> 观察：整场没有一道传统数仓八股，全部集中在 Agent 工程链路（RAG / Function Calling / Multi-Agent / 记忆 / 上下文）与效果评测（微调收益量化、Agent 评测 vs 问答评测）。其中 13、14、15 题本质是数据工程问题——训练数据从哪来、怎么清洗标注、怎么量化收益，这正是数据开发转 AI 方向最直接的切入点。
