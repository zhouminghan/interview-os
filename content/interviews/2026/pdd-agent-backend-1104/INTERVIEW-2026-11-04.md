# 面经记录（原始）

原帖为「啃下 5 轮面经」后的备考复盘，不是单场题目逐字记录，按原文 6 条建议整理：

1. 把简历上那个 Agent 项目做成「可被追问三层」的版本：业务价值 → 架构取舍 → 工程细节（状态、恢复、锁、缓存、降级、观测）→ 指标和踩坑。每个模块准备一个「为什么不用另一个方案」。
2. RAG 准备到「召回从 X 到 Y」的颗粒度：混合检索、Query 改写、Rerank 延迟、分块策略中文坑、父子知识库，这些拼多多都问过。
3. 上下文管理准备工程方案，不是概念：预算分配、压缩手段、tool_call/result 成对、prompt caching 命中、分层记忆。
4. 多 Agent 协作准备冲突和状态同步：Orchestrator-SubAgent、Debate、文件/资源归属、分布式锁粒度、断点恢复。
5. 后端底子别丢：Java 并发（AQS、线程池、锁升级）、JVM 调优、MySQL B+ 树/索引失效、Redis 缓存策略和数据结构、消息队列——拼多多就算 Agent 岗，这些该问照样问。
6. 算法按 LeetCode Medium 刷，ACM 模式练手写输入输出，重点：LRU、合并区间、二叉树层序、堆/栈、字符串回溯、并查集。

原帖结论：「拼多多这个 Agent 后端岗，面起来累，但方向是对的。它不是一个『追风口』的岗位，JD 里写的多智能体协作、高并发、BadCase 闭环，都是电商场景里真在落的东西。如果你后端底子扎实、又真的在 Agent 工程化上踩过坑，值得冲。把项目讲透，比什么都重要。」
