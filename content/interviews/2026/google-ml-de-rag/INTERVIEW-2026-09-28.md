# 面经记录（原始，图片 OCR）

> 数据工程师勇哥整理，Google ML Data Engineer onsite 权重最高一轮（45 分钟），全程围绕 RAG 数据管线开放大题。

## 原题：Design an end-to-end data pipeline for a RAG system

业务背景：海量网页原始文档用于 Gemini 类问答 RAG 检索，需入库→清洗→分块→质量过滤→生成 embedding→写向量库，同时产出模型评估数据集。

## 澄清问题（第一考点，不能上来直接画架构）

1. 文档数据规模、日均新增量、存量量级
2. 数据新鲜度 SLA：文档更新后多久同步到向量库
3. 吞吐量：检索 QPS、文档处理吞吐上限
4. 失败容忍度：处理失败丢弃还是重试，是否允许脏数据流入
5. 下游消费方：RAG 检索服务与评估数据集的需求差异
6. 成本约束、算力预算上限

（面试官追加：存量亿级网页、每日千万级新增、部分网页周期更新、检索延迟敏感、预算有上限、文档含隐私内容）

## 架构思路

1. 原始网页接入：Pub/Sub 消息接入 + Dataflow（Apache Beam）分布式处理，原始内容存 BigQuery 做元数据
2. 清洗与质量过滤：simhash 去重、过滤广告/导航/空白乱码、HTML 去标签、隐私脱敏（追问：完全文本一致 vs 语义重复的取舍）
3. 文本分块：固定长度 + 重叠窗口（追问：不同文档类型分块是否差异化、重叠窗口副作用）
4. Embedding 生成：批量离线为主、高频更新走少量实时，调 Vertex AI（最贵环节，做资源调度与批处理优化；追问：模型版本升级旧向量怎么办）
5. 向量入库：关联文档块元数据、支持高并发检索（追问：文档更新/删除增量更新、数据版本）
6. 产出评估数据集：抽样导出用于 RAG 召回离线评测

## 连环追问

- 脏数据、重复垃圾页的清洗去重策略
- 分块方式如何影响 RAG 召回
- Embedding 离线批量还是实时、怎么扩容
- 向量库选型理由、读写权衡、更新方案
- 文档/embedding 分布漂移监控
- 管线失败重试、幂等、断点续跑
- GCP 资源开销最大环节与降本
